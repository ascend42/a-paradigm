Your code, written down where agents answer to it.

Paradigm keeps a typed map of your codebase in plain YAML files next to the code, and agents read it through MCP tools instead of guessing. Hooks can stop a session that changed code and left the map behind.

Those checks are off until you turn them on. The default level is none.

Three things it holds an agent to.

An agent changes the code. The description of that code, its auth gate and the record of why all stay as they were. The next session starts from a picture that is no longer true, and nothing tells it so.

Structure

Each part of your code is described in a .purpose file beside it: its components, flows and signals. Authorization gates live in portal.yaml. The agent asks the map what exists and what a change touches. On our own repo that map holds 1,770 symbols.

Proof: paradigm status, section 2

Determinism

Hooks are shell scripts that run at fixed points in a session. They are not instructions an agent can skip. With enforcement on, the Stop hook blocks a session when code changed and its .purpose file did not. It is off by default, and you choose the level: minimal, balanced, strict.

Proof: packages/paradigm/src/core/enforcement/loader.ts, line 21

Calibration

A new learning is designed to be proposed, tested against scenarios and signed off before it reaches an agent's notebook. Since 8.1.1 it counts as survived only after two confirmed scenario runs, by a different agent. That is the design. We have no outcome data: on our own repo, paradigm doctor reads “FLATLINE: 0 journals / 20 completions”.

One session, start to finish.

  1. Ask the map

    Before the change, the agent asks what it touches. This is a real answer from this repo.

  2. Change the code

    The agent makes the change and updates the .purpose file in the same edit. The index picks it up on commit, or on demand with paradigm reindex.

    That command is not in 8.1.3 yet; until it ships, ask your agent to reindex.

  3. The hook checks

    When the session tries to stop, the Stop hook compares what changed with what was described. With enforcement on and a .purpose file left behind, the session is blocked until the agent fixes it. With the default level, nothing is checked. The hook takes about 1 s.

  4. The record is written

    The reason for a choice goes into a decision file. What happened goes into a lore entry. Both live in the repo, so the next session can read them. This repo holds 138 decisions and 710 lore entries.

    The decision format has fields for one decision replacing another. 0 of 138 files in this repo use them, so we show no example of it.

Limits

  • Checks are off until you set a level.
  • The hooks run in Claude Code and Cursor sessions.
  • Keeping .purpose files current is work the agent does on every change. We have not measured what it costs.
  • Almost every commit so far is by one person.

Requirements

  • Node 24 or later.
  • Claude Code or Cursor for the hooks. The plugin is for Claude Code.

The first thing to do.

  1. Install the CLI.

    npm install -g @a-company/paradigm

  2. In a real project of yours, set it up. One command.

    paradigm shift

    Run paradigm shift on a branch the first time. It writes new files into your repo and regenerates instruction files such as CLAUDE.md. Read the diff before you commit.

  3. In Claude Code, add the plugin.

    /plugin marketplace add ascend42/a-paradigm
    /plugin install paradigm@a-paradigm

  4. Say this to your agent, naming a module you know well.

    say to your agent Map this codebase with Paradigm: draft .purpose files for the main directories, then tell me what would be affected if I changed a module you know.

What you should see

An answer that names files you recognise. If it does, the map is working, and level 1 of the path is next. If it does not, run paradigm doctor and read what it says.

When you want the checks, turn them on: paradigm enforcement set balanced. Level 2 of the path walks through it.
