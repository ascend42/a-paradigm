01 — the mechanism

How Warpline works today

Git tracks bytes and reconciles them by matching lines. Warpline lifts every change into a graph of symbols — functions, config keys, contracts — and reconciles by whether those meanings commute. That single shift is the whole product.

The fabric

An append-only, content-addressed DAG of strands — one per sealed unit of work, each naming its parents. Nothing is ever rewritten; history is woven, not overwritten. It reconstructs byte-for-byte with git absent.

The selvage

The finished edge of the weave — the tip of a line of history that everything integrates into. Advancing it is a per-ref compare-and-swap: two writers can’t silently clobber the same edge.

A scratch & a knot

Each agent forks a private scratch lane to propose in. When two lanes change the same meaning to different values, the merge ties a knot — the one thing a human, never an agent, must untie.

Every admit returns one verdict — and each is a decision, not a guess

CLEAN · auto-fold

The two lanes touched disjoint meanings. They commute — Warpline weaves them with no merge step and no review. This is where it quietly beats git: disjoint work never conflicts, no matter how long the lanes ran apart.

FAST_ADMIT

The lane is a straight-line advance over the tip — nothing to reconcile. The edge moves forward.

KNOT

Both lanes changed the same symbol to different meanings, or the bytes genuinely overlap. Fails closed — sealed, refused, and handed to a human as a self-sufficient work order carrying both sides.

HELD

The verdict looked clean, but a changed path was byte-decided — a config value, a .js file, a bare constant meaning never lifted. Warpline holds it for a human rather than auto-fold something it couldn’t read.

Branches, merged by meaning

Git’s working folder holds one branch at a time, and parallel branches meet only at a manual, textual merge. Warpline’s new layer (M2.5) gives you durable, named, switchable branches — and merges them the way it admits: by meaning.

CLEAN — folds automatically KNOT — a human resolves HELD — meaning-blind, human confirms selvage / protected edge

Protected main

A swarm can fork, propose, and merge freely among feature branches — but an agent can’t auto-land into the integration line. Merging into protected main is human-only, so no agent can launder work past the review gate.

The calibration moat

Every outcome — did this symbol survive, or get reverted? — grades the codebase’s own trust, scoped to real DAG ancestry so a doomed branch can’t poison main. It’s per-repository and can’t be copied: the moat is the memory of this code.

Mirror mode

Warpline runs its own native object store git-absent, or rides alongside git — git as the durable backstop while Warpline adds the meaning layer. You never have to leave git to start.

02 — the map

Git, mapped onto the weave

Git stores bytes and reconciles by matching lines. Warpline stores a snapshot and its meaning and reconciles by judgment. That inverts which features are hard — and the one you’d expect to be work, snapshots, turns out nearly free.

Tags & releases — every strand is already a snapshot

A git tag names a commit, and a commit is a tree snapshot. In Warpline every sealed strand already binds a byte-exact tree — so you don’t make a snapshot to tag, you just name a strand. It works today with the primitives: warpline refs set v1.0 pick:… then warpline restore v1.0 reconstructs that exact tree, git absent. What’s pending is only the ceremony — a branded tag verb, and signed releases, which wait on M3 integrity. A release is a named strand + its intent as notes + an attest freeze (+ a signature, at M3).

The through-line: snapshots — tags, releases, checkout of any point — are nearly free, because every strand already carries a byte-exact tree. History rewriting is intentionally off the table. And the features that get better — merge, blame, diff, revert — are exactly the ones git does textually. What’s left to match git’s surface is notarization (signing, M3) and distribution (remote, M4).

03 — the arc

What Warpline is, and what it becomes

Warpline started as a lens that could read a merge and became an engine that can run one. The line below is the real build order — each era earned by the one before it.

era oneshipped

The meaning lens

Lift code and config into a symbol graph; diff by meaning, so a rename is an empty change and a moved constant is a real one. The insight the whole product rests on.

era two — M1shipped

The native fabric

A content-addressed object store and hash-chained ledger that reconstructs any state byte-for-byte with git absent. Durable merge bytes, restore, verify — the substrate that makes Warpline a place work can live, not just a lens over git.

era threeshipped · cleared

The judge & the instruments

A standalone, blind LLM-judge — built to falsify the core claim that “clean means safe,” security-cleared, tamper-evident. Plus the honesty valves: contested-denominator counting, byte-only surfacing, the injection-hardened rating card.

era fourshipped

Dogfoodable

warpline init, git-absent status, a native .warpignore, agent onboarding baked into notebooks. A fresh project can be tracked — and two Claude Code instances on one machine were proven to weave, knot, and resolve a real contest.

now — M2.5functionally complete

Branches, merged by meaning

Durable named branches, switch, and merge by meaning with the fail-closed rule — the thing git structurally can’t do, delivered with safety git can’t offer. The advocate’s falsifier passes: the canonical config-and-invariant breaks are held, not silently sealed.

nextdesigned

Concurrency & measured trust

Narrow the global lock so disjoint branches admit in parallel (per-branch compare-and-swap). Run the field test live — the LLM-judge measuring the real false-clean floor. Turn the trust moat from “wired” into “calibrated on real outcomes.”

then — M3planned

Integrity

Sign the strands, witness the branch heads. Today the agent/human boundary rests on an unsigned convention; M3 makes it cryptographic — the cardinal source-control property for an adversarial, multi-writer world.

the penultimate goal — M4deferred

Remote & sync

Clone, push, pull for the fabric — so your Mac and your Windows box collaborate on one shared weave, not two. The distributed version of the thing that already works on one machine.

the whole pointthe horizon

Source control for the agentic age

Published, calibrated per codebase, with a viewer anyone can point at any directory. The layer where meaning judges, bytes execute, and a swarm of agents builds without stepping on each other — and without a human hand-merging every lane.
