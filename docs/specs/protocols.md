# Protocols — Repeatable Implementation Patterns

> Learned procedures with exact references. The agent's first stop before exploring.

## Problem

AI agents routinely spend 100-200k tokens exploring codebases to reverse-engineer
implementation patterns before they can start working. Protocols fill that gap —
procedural, step-by-step instructions with exact file references, learned from
actual completed work.

## Storage

```
.paradigm/protocols/
  index.yaml            # Auto-generated by reindex (summary + health)
  add-view.yaml         # One file per protocol
  add-api-route.yaml
```

## Schema: Protocol File

```yaml
id: P-add-view
name: "Add a new view"
description: "Create a new page/view with its own store, route, and CSS section"

trigger:
  - "add view"
  - "new page"
  - "create view"
tags: [ui, frontend, view, page]
symbols: ["#logs-view", "#events-view"]
exemplar: "ui/src/views/LogsView.tsx"

steps:
  - action: create
    target: "ui/src/views/{Name}View.tsx"
    template_from: "ui/src/views/LogsView.tsx"
    notes: "Functional component, named export"

  - action: modify
    target: "ui/src/App.tsx"
    reference: "Route elements"
    notes: "Add <Route path='/{name}' element={<{Name}View />} />"

  - action: verify
    notes: "Run build, check route loads"

recorded_from: "L-2026-03-01-001"
recorded_at: "2026-03-01T10:00:00Z"
last_verified: "2026-03-01T10:00:00Z"
verified_by: "claude-opus-4-6"
status: current  # current | stale | broken
```

### Step Actions

| Action | Meaning | Fields |
|--------|---------|--------|
| `create` | Create a new file | `target`, `template_from`, `notes` |
| `modify` | Edit an existing file | `target`, `reference`, `notes` |
| `run` | Execute a command | `command`, `notes` |
| `verify` | Confirm something works | `notes` |

### Placeholders

`{Name}` (PascalCase) and `{name}` (kebab-case) in step targets.

## MCP Tools

| Tool | Tokens | Purpose |
|------|--------|---------|
| `paradigm_protocol_search` | ~200 | Fuzzy search by task description |
| `paradigm_protocol_get` | ~300 | Get specific protocol with freshness |
| `paradigm_protocol_record` | ~100 | Record new protocol |
| `paradigm_protocol_update` | ~100 | Update/refresh a protocol |
| `paradigm_protocol_validate` | ~200 | Validate references and health |

## Fuzzy Search

Tokenizes the task, scores against:
- `trigger` phrases (weight 3)
- `tags` (weight 2)
- `name` + `description` (weight 1)
- Step `notes` (weight 0.5)

## Freshness

Three mechanisms:
1. **Reindex validation** — Missing files → broken, modified exemplar → stale
2. **On-use refresh** — Agent calls `protocol_update` with `refresh: true` after following
3. **Status visibility** — `paradigm_status` includes protocol health counts

## Lore Integration

When `paradigm_lore_record` detects 2+ new files in a directory with existing
similar files, the response includes a `protocol_suggestion` with a draft protocol.
