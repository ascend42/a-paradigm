Locked nomenclature: a change = a **PICK** (a Justification); merge = **WEAVE**; fold N independent branches = **CONSOLIDATE**; meaning→code = **PROJECT**; follow a symbol = **LIFELINE**; conflict = a **KNOT** you **DECIDE**; live edge = the **SELVAGE** (HEAD); release = a **BOLT**; consolidated history = the **FABRIC**; the woven-history view = the **TAPESTRY**; a PR-equivalent = an **OFFER**; trust-weighted approval = an **ENDORSEMENT**.

## 1. The complete flow map (every git flow → Warpline)
Classification: MAPS-CLEANLY · TRANSFORMED · NEW-IN-WARPLINE · OBSOLETE.

**Local everyday:** init→`warpline init` · clone→`warpline clone` · **add/staging → OBSOLETE** (you stage *meaning*; the pending semantic-delta IS the stage) · commit→`warpline pick` (TRANSFORMED: seals a Justification) · branch→`warpline branch` · checkout/switch→`warpline switch` (+PROJECT) · merge→`warpline weave` (TRANSFORMED) · **rebase → mostly OBSOLETE** (linearize-for-cleanliness vanishes when history is a meaning-DAG; replay-onto survives as `warpline replay --onto`; interactive reword/squash/reorder/drop are meaningless or = amend/revert) · cherry-pick→`warpline pick-replay` (by essence, not patch-context) · stash→`warpline shelf` (GAP-2) · tag→`warpline bolt` · log→`warpline tapestry` · diff→`warpline diff` (semantic) · show→`warpline show` · **blame→`warpline lifeline`** (meaning-attribution, survives renames) · status→`warpline status` · reset→`warpline unpick`/`warpline reset` · revert→`warpline revert` (forward inverse PICK) · reflog→`warpline reflog` (GAP-3) · bisect→`warpline bisect` (by symbol/ripple; GAP-4) · clean→`warpline clean` · **mv→`warpline move`** (the ZERO-DIFF rename = the empty delta) · rm→`warpline remove`.

**Remote/collab:** remote→`warpline track` · fetch→`warpline gather` · pull→`warpline draw` (gather+weave) · push→`warpline offer` · clone→`warpline clone` · fork→`warpline diverge` · upstream→`warpline track`.

**The social/review layer git exiled to GitHub (Warpline owns it natively — all NEW-IN-WARPLINE):** PR→`warpline offer`/`warpline propose` · code-review→`warpline review`/`warpline scrutiny` · approve→`warpline endorse` · request-changes→`warpline request-changes` · protected-branch→`warpline protect`/`warpline law` · CODEOWNERS→`warpline owners` (computed domain-trust holders, not a file) · required-reviewers→trust policy · CI-checks→`warpline checks` (signed attestations on picks) · draft-PR→`warpline offer --draft` · merge-queue→`warpline queue` (Oracle re-predicts each landing).

**Plumbing/config:** hooks→`warpline hooks` (most byte pre-commit hooks OBSOLETE — meaning invariants live in the WARP) · `.gitignore`→`warpline ignore` (shrinks: files with no symbols were never meaning) · submodules→`warpline link` (by stateId; GAP-6) · worktrees→`warpline worktree` · gc→`warpline compact` · sparse-checkout→`warpline project --scope` (semantic sparse) · shallow→`warpline clone --depth` · **LFS → OBSOLETE** (Warpline never put bytes in history; big binaries are content-addressed blob attachments) · **`.gitattributes` → OBSOLETE** (EOL/text-binary/merge-drivers are byte-projection concerns; meaning has no line endings) · config→`warpline config` · notes→`warpline annotate` (largely subsumed — intent/ripple are already in the PICK).

**NEW-IN-WARPLINE (git never had these):** `warpline oracle` (built), `warpline heatmap`, `warpline lifeline`, `warpline consolidate` (N branches at once — the killer), `warpline weave --preview`, `warpline project`, the whole review/trust layer, `warpline trust`/`warpline whois`.

## 2. The WEAVE process — merge / discussion / approval (Loid)
A merge in git is a byte op a human blesses; a weave in Warpline is a meaning op the system already understands, so the only question left for a human is the one humans are better at: is this *intent* correct where the machine is uncertain and the symbol is fragile. **Review is attention routed by expected loss; trust schedules that attention, it never replaces it for fragile symbols.**

- **THE OFFER (PR-equivalent):** lifted from a branch (like `absorb`), correct-by-construction, carrying the **Justification** (actor, intent, semantic-delta, store-**computed** ripple, signature) + the author's **predictedRipple** (a separate, author-supplied forecast with a confidence — the calibration probe) + computed scrutiny + the Oracle verdict (autoClean/knots/dangling). Two fields git can't have: computed blast-radius (the author can't under-report impact) and the graded forecast (Warpline records what you *believed* about what you changed, and grades the belief).
- **SCRUTINY = fragility(symbol) × (1 − trust(author, domain))** — expected loss. `fragility` from history-fragility (break-history + blast-radius); `trust` domain-scoped from the **Classroom** (repeat-failure-rate, calibration, certified domains). Collapses to ~0 when the symbol is robust OR the author is proven — exactly where you want zero human attention. **The policy ladder:** Tier 0 auto-weave (clean ∧ low scrutiny ∧ no fragile symbol — logged, → Shadow Panel) · Tier 1 peer endorse (a domain-trust-holder signs) · Tier 2 **mandatory human** (scrutiny high OR any fragile symbol OR knots OR dangling — trust can't substitute) · Tier 3 Knot Council. Reviewers are **computed**: the top domain-trust holders for each touched symbol (CODEOWNERS without the file), ≥1 human for Tier 2+, ≥1 different-lens (anti-collusion).
- **DISCUSSION lives on the KNOT** (not diffuse PR prose). A knot (two intents binding incompatible meaning to one symbol — the Oracle already emits these) opens a **Knot Council**: the two intents + rationale + the blast-radius shown to every participant; resolving it writes a permanent **Decision** (`paradigm_decision_record`) anchored to the symbol's *essence* (survives renames, unlike a git line-comment), queryable next time the symbol knots, and fed to the Classroom as a calibration event. Repeated knots on a symbol raise its fragility → raise future scrutiny. Lightweight notes (Tier 1/2) anchor to a SemDelta/symbol, not a byte range.
- **APPROVAL = a trust-weighted ENDORSEMENT** (signature + endorser domain-trust-at-the-time over the Offer's stateId). Approved when Σ endorsement weights clears each touched domain's `required(symbol)` (which scales with fragility). **Auto-approve only at Tier 0**; **fragile symbols carry a typed ≥1-human requirement no agent-trust can fill** (the loaded-gun guard, layer 1). Layer 2 = the **Shadow Panel**: every auto-woven change gets counterfactual after-the-fact review; rising Shadow "would-reject" rate means trust is over-calibrated and τ_low must rise (the falsifiability guard — the Classroom poison-pill applied to the gate).
- **THE WEAVE-IN** writes a permanent **WeaveRecord** {weft, predictedRipple frozen, endorsements + trust-at-time, knotResolutions, gateTier, fieldOutcome: pending}. The **self-closing loop** reuses the Classroom field-failure reducer (same orchestrationId join key): a woven change breaks in the field → attributes to the author (calibration: predicted-safe but broke → trust ↓), each endorser (trust ↓), and the symbol (fragility ↑) → the author's next change in that domain is reviewed harder. **One trust ledger serves both the weave gate and the learning loop** — which is why this couples to the Classroom (build Classroom-first or -parallel).
- **HUMANS + AGENTS:** agents propose/review/endorse exactly as humans (trust keys on their Classroom identity); two high-trust agents can consolidate robust symbols with no human; the fragility floor pulls a human in precisely where expected-loss is high. Surfaced on the Conductor cockpit: THE BRIDGE = scrutiny-heat over N parallel branches; THE LIGHTBOX = knot decision cards (render-by-projection of the real blast radius); THE TAPESTRY = WeaveRecords graded by field outcome.

## 3. Collaboration / remote / distribution (Aegis)
First principle: git's unit of sharing is a byte-blob by SHA; Warpline's is a **meaning-object by contentId**. Sharing is **set-reconciliation over content-addressed meaning** — two people who reach the same meaning produce the same node; dedup is intrinsic; the wire payload is a fraction of git's.

- **Distributed + local-first:** every clone is a full WARP; no privileged "origin." Three transports — peer-to-peer, a **relay** (nevr.land or self-hosted — a dumb gossip post office, never an oracle), and signed **bundles** (sneakernet) — all use one reconciliation handshake. Offline is the default mode; content-addressing makes independently-derived identical meaning converge for free.
- **THE TWO-PHASE INVARIANT (security-load-bearing): transfer ≠ admission.** `gather` (git fetch) transfers the contentId-set difference + signed wefts but changes nothing; `weave` admits a weft into your fabric, trust-gated. `draw` (git pull) = gather + weave. **You can gather from a stranger safely** — receiving signed meaning is inert; nothing enters your fabric until a weave passes your policy. `offer` (git push) *proposes* deduped meaning-objects + custody signatures; you can never force meaning into a peer's fabric. clone→`warpline clone`, remote→`warpline track`, fork→`warpline diverge`, ls-remote→`warpline selvage`.
- **PROTECTED FABRIC = WEAVE-LAW**, the CODEOWNERS-equivalent as a *trust predicate*, not a server config: the fabric is partitioned by symbol-domain; each domain has a trusted-author set; a weave into domain D is admissible iff the signer is in D's trusted set **as computed by the weaving node's own trust function** (admissibility is subjective — clones may legitimately disagree; the "canonical fabric" is the trust-weighted quorum view). WEAVE-LAW is itself a signed meaning-object — changing it is a pick that must satisfy the *prior* law.
- **IDENTITY + SIGNING = the Custody Chain** (human operator key → runtime/model → agent archetype + notebook-hash; agent identity *is* hash(training), unforgeable). Offline verification checks integrity (recompute contentId/Merkle), authorship (the hash-bound sig-chain), agent identity (the notebook hash), and **ripple honesty** (a pick that lies about what it touched is self-falsifying). Agent signing at machine scale = a **session-scoped delegation cert** (operator delegates scoped/time/count-bound authority once; the agent signs with the session key; a leaked key is bounded + revocable).
- **TRUST DISTRIBUTION = web of trust, no central authority.** Trust is local/subjective/edge-computed; two clones disagreeing is correct. Trust travels as **signed, replayable evidence** (not scores) gossiped via the relay; you can re-run the evidence and decide for yourself (laundering fails because the evidence IS the claim). **Quarantine:** a fresh teammate/agent starts at zero local trust — their offers are gathered (inert) but non-admissible; their picks land in a quarantine selvage until accumulated replayable evidence clears your threshold. Symmetric for new humans and new agents.
- **Attack surface:** malicious-peer-push (admission is trust-gated → quarantine), provenance forgery (hash-bound sig-chain + notebook-hash identity), trust laundering (replayable evidence only), poisoned meaning-object (content-addressing detects substitution; admission needs a signed weft; ripple-honesty catches lies), cold-start (quarantine), force-weave/history-rewrite (no force primitive; a rewrite is a *divergent* fabric, not a silent overwrite; bolts are signed cuts), malicious relay (a post office with no keys can censor but not forge; multi-relay + p2p fallback). Net: the dangerous operation (admitting to your fabric) is *always yours to gate*.

## 5. GAPS — flagged loudly (Cid)
- **GAP-1 (biggest): non-symbol files** — config/prose/fixtures/images carry no Paradigm symbol; what is truth for a file with no meaning? Until decided, diff/weave on these degrades to byte-merge (the very thing Warpline replaces). Options: byte-blob attachment (loses semantic merge) vs a "text-meaning" essence for prose. Needs founder + Loid + Cid.
- **GAP-7 (interop lifeline): git EXPORT round-trip** — `export --git` must reconstruct byte-commits from meaning-PICKs; a git→warpline→git round-trip without drift is unproven. Must not be hand-waved.
- GAP-2 stash/shelf edge semantics · GAP-3 reflog↔compact retention/GC · GAP-4 bisect's test-exit→meaning bridge · GAP-5 versioning (not just attaching) binary assets · GAP-6 cross-WARP trust composition for `link`.
