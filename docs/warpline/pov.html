01 · The thesis

WARP is truth. Bytes are a projection.

Git versions the file — the photograph of the bytes. Warpline versions the meaning: every symbol's kind, contract, and typed edges. The bytes become one renderable projection of a deeper truth, the way source is a projection of intent.

  • A change is a PICK — it carries its actor, its intent, its semantic-delta, a store-computed ripple it can't under-report, and a signature. Conscience travels with the change.
  • A rename is nothing — same meaning, same contentId, an empty delta. A move across files is nothing. Git sees churn; Warpline sees identity.
  • A merge is a weave — N non-intersecting branches fold into one fabric with zero human merge labor; only a genuine meaning-collision (a knot) asks for a human.
  • The Oracle already catches what Git can't: on real code in this repo, Git merged clean and Warpline caught a call into a retired symbol. That test passes today.

Honest caveat — the lens is lossy

"WARP is truth" holds for the merge decision — that's proven. But materializing code still projects from stored bytes, so the lens is lossy, and the word replacement is earned, not yet shipped. We say what's true: the Oracle is real; the rest is being woven.

02 · Where it stands

Built, designed, latent — and honestly, not yet.

No vaporware. Here is the real state of the four layers.

Built & proven

The Oracle & the code-lens

ABSORB lifts a ref into a WARP; the Convergence/Divergence Oracle runs Git's real merge read-only and scores it against meaning. A v1 reads actual TypeScript (CCNF essences, checker-resolved refs). The divergence proof is a green test. And since M1: a native byte store, pick/admit/seal writing a hash-chained fabric, and restore rebuilding a working tree with git absent.

RUNS TODAY

Designed

The surfaces

The Oracle Divergence Viewer and Semantic-Diff are built in the Platform; the Fabric and Lifeline navigation views are designed (the section below). A full design system — tokens, components, screens — anchors them.

DRAWN, WIRING NEXT

Latent

The rest of the write path

Picks now seal into a native, hash-chained fabric; admission (FAST_ADMIT / CLEAN / KNOT / DANGLE) and knot resolution are live. Still latent: multi-generation merges, named lines (branching), the trust ledger, scrutiny routing, and the endorsement primitive.

PARTS EXIST

Not yet

Writing & the round-trip

Warpline now writes its own history — but it does not yet weave meaning → code (bytes are materialized from the stored projection), attribution is hash-chained yet unsigned, and the Git export round-trip (GAP-7) — reconstruct byte-commits from meaning-PICKs without drift — is unproven. This is the gate. We won't hand-wave it.

THE GATE

03 · The one move

A read-only oracle is a linter. The value is in the weave.

A four-lens product review landed on this unanimously: the write path + the Git round-trip (GAP-7) is the gate to the product, the moat, and the wedge. The first half is now real — picks seal into a native fabric, and restore works with git absent. What remains of the gate: the Git round-trip proven drift-free, and the calibration ledger accruing real graded history — that's what turns a demo into infrastructure.

Go-to-market — companion first

Warpline Guard

Ship the Oracle as a CI check that fails the build on a meaning-break — a call into a deleted symbol, a contract change Git merged clean. It rides alongside Git. No migration, no risk, immediate proof: "we ran your tool and it caught a break that shipped."

Then — replacement by gravity

Not a frontal assault

"Rip out Git" loses. Own the agent review/merge layer first — the place agents already break meaning fastest. Once teams trust the weave more than the merge, replacement happens by gravity, not by pitch.

04 · Who it's for

The wedge: AI-agent-heavy TypeScript teams.

Pick the room where the pain is sharpest and the lens is strongest.

  • Agents merge fast and break meaning silently. A human reads a diff; an agent ships ten. The faster the merge cadence, the more a byte-clean merge hides a meaning-break — exactly what the Oracle catches.
  • TypeScript, because the code-lens is bounded there. A v1 already reads TS meaning end-to-end. We lead where we can tell the truth about the code, not everywhere at once.
  • This repo is user zero. Warpline runs on its own history — the dog-food forcing function. The Fabric and Lifeline below render this codebase's real topology and real Oracle verdicts.

05 · Why it compounds

The moat is a history. The clock hasn't started.

Every weave, every resolved knot, every field outcome accrues a non-portable calibration corpus — who is trusted on which symbols, which symbols are fragile, whose forecasts held. It can't be exported, scraped, or cold-started. A competitor can copy the engine; they can't copy your fabric's history.

  • SCRUTINY = fragility(symbol) × (1 − trust(author, domain)). Attention routed by expected loss — earned from real outcomes, not bought.
  • The loop is self-closing. A woven change that breaks in the field lowers the author's and endorsers' trust and raises the symbol's fragility — so the next change there is reviewed harder. The corpus sharpens itself.
  • And it's worth ~0 until weaves accrue. Which is the whole point: the moat starts when the write path ships. The clock only runs once Warpline writes — another reason the gate is the strategy.

06 · The founder's question — answered

You have to be able to see the weave.

The verdict and diff screens told you what a merge meant — but there was no way to navigate the history the way SourceTree's commit graph lets you. Two surfaces answer it, both through the meaning lens, both deterministic — never a force-directed hairball, which would break the very thesis the product rests on.

The Fabric — the oracle's verdict lives on the weave node. Calm teal = convergent · seam knot = divergent.

The Lifeline — blame by meaning. One unbroken thread where git blame shatters into three mis-attributed spans.

The history you can read at a glance — and the one Git's git log --graph can't draw.
