# paradigm beacon

Generate a quick-start orientation file for AI agents to understand your project structure instantly.

## Overview

Creates `.paradigm/beacon.md` - a compact, agent-optimized summary providing immediate context without reading everything. Think of it as a "README for AI agents".

## What It Does

**Generates a markdown file with:**
- **Constellation map** - Visual overview of features, components, and their relationships
- **Portal summary** - Authorization gates and access control
- **Landmarks** - Key files (config, types, API utils, etc.)
- **Pathways** - Available task prompts (add-feature, refactor, debug-auth, etc.)
- **Symbol reference** - Quick symbol system reminder
- **Context pointers** - Where to find detailed info

**Uses as input:**
- All `.purpose` files (features, components, flows)
- `portal.yaml` (authorization gates)
- Key project files (package.json, tsconfig.json, etc.)
- `.paradigm/prompts/` directory

## Why You Need It

**For AI agents:**
- **Fast orientation** - Get project overview in seconds, not minutes
- **Token-efficient** - ~2-5KB vs reading dozens of files
- **Structured navigation** - Know where to find what
- **Task discovery** - See available workflows

**For developers:**
- **Project overview** - Quick glance at structure
- **Onboarding** - New team members start here
- **Documentation** - Living project map

## When to Run It

### ✅ Run after:
- **`paradigm init`** - Generate initial beacon
- **Adding features** - New #features, #components
- **Restructuring** - Major code organization changes
- **Team onboarding** - Fresh beacon for new members

### 🔄 Periodic:
- **Weekly** - If actively developing features
- **After sprints** - Capture new structure
- **With constellation** - Keep both fresh

### ⏩ Fast operation:
- Runs in ~50-200ms
- Safe to run frequently

## Usage

```bash
# Generate beacon (default location)
paradigm beacon

# Custom output location
paradigm beacon --output ./custom/beacon.md

# Force refresh (overwrite existing)
paradigm beacon --refresh

# Quiet mode (no console output)
paradigm beacon --quiet

# JSON output (for tooling)
paradigm beacon --json

# Target specific directory
paradigm beacon ./src
```

## Beacon Structure

```markdown
# Beacon - my-project

> Quick-start orientation for AI agents. Generated by Paradigm.

## Constellation (Symbol Map)

#checkout           → src/features/checkout → ^authenticated, ^payment-ready
#dashboard          → src/features/dashboard → ^authenticated
#Button             → src/components/Button.tsx
#Modal              → src/components/Modal.tsx
... and 8 more features
... and 15 more components

## Portals (Authorization Gates)

- `^authenticated` - User must be logged in
- `^admin` - Admin access required

## Landmarks (Key Files)

- `portal.yaml` - Authorization topology
- `src/types/index.ts` - Type definitions  
- `package.json` - Package manifest
- `.paradigm/config.yaml` - Paradigm config

## Pathways (Common Tasks)

- "Add feature" → `.paradigm/prompts/add-feature.md`
- "Refactor" → `.paradigm/prompts/refactor.md`
- "Debug auth" → `.paradigm/prompts/debug-auth.md`

## Symbol Quick Reference

| Symbol | Type | Meaning |
|--------|------|---------|
| `#` | Component | Any documented code unit |
| `^` | Gate | Authorization checkpoint |
| `!` | Signal | Event for side effects |
| `$` | Flow | Multi-step process |
| `~` | Aspect | Rule with code anchor |

## For More Context

- Full symbol graph: `.paradigm/constellation.json`
- Detailed specs: `.paradigm/specs/`
- Session history: `.paradigm/thread.md`
```

## Tips & Gotchas

**Pro tips:**
- Beacon is fast - run liberally
- Read beacon.md yourself for project overview
- Use with MCP: agents can read it automatically
- Shows up to 10 features/5 components (prevents huge files)
- Truncated lists show "... and N more"

**Watch out for:**
- Beacon shows overview, constellation has full details
- Won't update automatically - run `--refresh` after changes
- Empty projects generate minimal beacons
- Landmarks are auto-detected (common file patterns)

## vs Constellation

**Beacon:**
- Human-readable markdown
- Quick overview (~2-5KB)
- Selected highlights
- Read first for orientation

**Constellation:**
- Machine-readable JSON
- Complete graph (~50-500KB)
- All symbols and relationships
- Read second for detailed analysis

Use both - beacon for speed, constellation for depth.

## What Shows in Beacon

### Features (up to 10)
```
#feature-name → path/to/feature → ^required-portals
```

### Components (up to 5)
```
#ComponentName → path/to/component
```

### Gates (up to 6)
```
- `^gate-name` - Description from portal.yaml
```

### Landmarks (up to 8)
Auto-detected key files:
- portal.yaml
- src/lib/api.ts
- src/hooks/useAuth.ts
- src/types/index.ts
- package.json
- tsconfig.json

### Pathways (up to 6)
Prompts from `.paradigm/prompts/`:
- add-feature.md
- refactor.md
- debug-auth.md
- trace-flow.md

## Troubleshooting

**Problem: "Beacon empty or minimal"**
- Solution: Ensure `.purpose` files exist with features/components
- Check: `paradigm status` to verify symbols

**Problem: "Missing features in beacon"**
- Solution: Beacon shows top 10 - check constellation.json for full list

**Problem: "Landmarks not showing expected files"**
- Solution: Landmarks are auto-detected - file must exist at expected path

**Problem: "Pathways section empty"**
- Solution: Create prompt files in `.paradigm/prompts/`
