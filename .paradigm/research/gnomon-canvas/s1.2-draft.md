- S1.2 publishes the dimension vocabulary (`dim-shape:v1`, `content-palette:v1`), a pure tolerant fold and a strict write validator in `gnomon-contracts`.
- It makes the two batched contract moves and adds the host hooks that stamp `payload.relayedFor` and row `causes` on mod appends.
- No mod, GUI leaf, MCP bridge or tool is built here.

Palette validation rule (`contentPaletteProblems`, run by a unit test and at module load):
- names match the pattern and are unique;
- every `day` and `night` value is lowercase `#rrggbb`;
- every swatch value is at least `CONTENT_MIN_DISTANCE_SQ` from every reserved colour of the same theme;
- no swatch name equals a reserved colour name.

Distance is integer redmean: `((512+r̄)·ΔR² >> 8) + 4·ΔG² + ((767−r̄)·ΔB² >> 8)`. It is integer so two engines never disagree at the threshold.

`custom:#rrggbb` is stored as written and snapped at resolve time:
- while closer than the minimum to any reserved colour of the theme, step each channel 8 units away from the nearest reserved colour (plus 8 on all channels if identical), clamped to 0..255;
- at most 32 steps, then fall back to the first swatch;
- the night value is `snapCustomColour(nightOf(hex), 'night')`.

No render path can produce a reserved colour, and the stored token never changes.

**Tolerant fold** (reads never refuse; rows are permanent):
- A row whose kind is not one of `DIM_KINDS`, or whose `payload.dim` differs from the state's, leaves the state unchanged.
- A malformed payload or a non-array `ops` adds 1 to `unapplied`.
- `add` needs only a string `node.id` that is neither live nor in `gone`. The whole node object is deep-copied in, including unknown kinds and unknown fields.
- `update` shallow-merges `patch`; `null` removes a key; `id` and `kind` in a patch are ignored.
- `move` adds `dx`/`dy` when both are integers and the node's `x`/`y` are numbers.
- `delete` removes the node and adds the id to `gone` (ids are never reused).
- `lock`, `unlock`, `clear` and any unknown `type` change nothing and add 1 to `unapplied`. Their semantics arrive with a higher `v` on the row.
- A row with `v > 1` is folded by these rules for the op types v1 knows.
- The keys `__proto__`, `constructor` and `prototype` are dropped at any depth while copying.
- `by` comes only from the row's `payload.relayedFor`: `cls` is `agent` when `relayedFor.agent` is a string, otherwise `human`. A row without a well-formed `relayedFor.principal` applies its ops with `by = {cls: 'human', principal: 'unknown'}`.

**Canonical hash input** (G-DDL-04):

```ts
canonicalJson({
  schema: 'dim-shape:v1', dim: state.dim, title: state.title,
  nodes: [...state.nodes.values()]
    .sort((a, b) => (a.node.id < b.node.id ? -1 : 1))   // by id, code-unit order
    .map((n) => ({ by: { principal: n.by.principal, ...(n.by.agent ? { agent: n.by.agent } : {}) }, node: n.node })),
})
```

- `node` carries every field, known and carried through, so unknown kinds and fields are hashed.
- `by` sits beside `node`, so a carried field named `by` cannot collide.
- Excluded: `seq`, `addedSeq`, `connId`, `surface`, `hsid`, `attached`, `gone`, counters. The same ops replayed at other seqs hash the same.
- No Unicode normalisation in the hash; strings are hashed as stored.
- `canonicalJson` is the existing serializer (V `internal.ts:239`).
- One fixed vector (ops plus the resulting hash) goes into the client API descriptor, the way the auth vectors do (V `client-api.ts:83-99`), so a changed layout moves `clientApiId`.

**Writes** (`validateDimOps`, strict, C4):
- More than 64 ops: `too-many-ops`.
- `lock`, `unlock`, `clear`: `op-not-available`. Any other non-writable type: `op-unknown`.
- A kind that fails the grammar: `kind-unknown`. A namespaced or non-core kind: `kind-not-core`.
- Any key outside `DIM_NODE_KEYS[kind]`, in `add.node` or in `update.patch`: `field-unknown`. A `by` or `relayedFor` key lands here too.
- Coordinates, sizes, `dx`, `dy`, `points` and `rot` must be safe integers in range.
- `color` and `fill` must pass `isContentColour`.
- `from`, `to` and `parent` must name a node live at that point in the batch; `parent` must be a `frame`; a frame has no parent.
- An agent actor may `update`, `move` or `delete` only nodes whose `by` matches its own principal and agent (`not-owner`). A human may edit anything.
- Ops are validated in order against a running copy of the state, so a later op can cite an id an earlier op added.
- `fix` is a fixed string per code and never echoes input.
- `field` is the `DIM_FIELDS` name, else `'unknown'`.

**Secret check:**
- `dimTextForScan(s)` is `s.normalize('NFKC')` with every `\p{Cc}`, `\p{Cf}`, `\p{Zl}` and `\p{Zp}` code point removed (controls, zero-widths, bidi marks, BOM, soft hyphen, tags, line and paragraph separators).
- Scanned: every string value at any depth of every op, and for each node an op touches, every string of the node as it stands after the op plus the concatenation of those strings in key order. The second catches a secret split over two updates or two fields.
- Any hit sets `secret: true`, returns `ok: []` and one `refused` entry per hit with code `secret`. The batch is all-or-nothing.
- Only the rule kind is reported, never the text (the convention of V `kernel/loops/secret-scan.ts:9`).
- The default scanner uses a rule table moved into contracts (O4).
- Stated residual: a secret split across two nodes, or broken by ordinary spaces.

**`refs[]` (C3), `validateDimRef`:**
- At most 8 per node, no duplicates (`ref-count`).
- A string of at most 128 characters (`ref-too-long`).
- Must match `^(sym|spec|td|l|t|n|s|wl|knot|dim):[A-Za-z0-9#$^!~][A-Za-z0-9._/#$^!~-]*(@[A-Za-z0-9][A-Za-z0-9._:-]{0,31})?$` (`ref-scheme` for a scheme outside the list, else `ref-bad`).
- No `..` and no `//`.
- Must pass `validateRefV1` strict and equal its own alias expansion (no bare `#foo`).
- Refs pass through the secret check like every string.
- In S1 they appear only in `dimViewOf` output as plain strings, never resolved, never a link.
- Reason for the separate rule: `parseRef` takes any non-whitespace id, and `card`, `permit`, `gkey`, `hsid` are registered schemes (V `ref.ts:22-36,85`).

**Units and `z`:**
- One board unit is one scene pixel at zoom 1; y grows downward; every coordinate is an integer. The engine mapping rounds with `Math.round`.
- `z` is a base-62 string over `0-9A-Za-z` in ASCII order, compared by code unit, ties broken by node id, never ending in `0`.
- `dimZBetween(a, b)` returns the shortest string strictly between them by digit-wise midpoint (`null` means open end).
- Why this scheme: it sorts identically in JS, SQLite and JSON with plain string comparison, and a reorder is one `update` of one node with no neighbour renumbering. That is what A3 needs for team editing.
- The mapping never passes `z` to the engine as its own index. Forward it emits elements in `(z, id)` order; in reverse it derives `z` for a new or moved element from its neighbours with `dimZBetween`. (I: Excalidraw 0.18 validates and may rewrite its own `index` values; not checked in `node_modules`.)

**`hsid` for GUI rows (reader side):** `dimHsidOf(state, row)` returns `row.payload.relayedFor.hsid` when present (tool rows), else the single entry of `state.attached` at that row, else `null`. `attached` is folded from `session.start.attached` and `attach` rows. It is never an op argument.

**`dimViewOf` (C4):**
- A core node shows its `DIM_NODE_KEYS` fields plus `by`.
- A non-core node shows `{id, kind, x, y, by}` where `kind` is the kind string if it matches `DIM_KIND_PATTERN`, else `"unknown"`.
- Carried-through fields are omitted entirely.
- The legend is built from kinds and `by` only.

Design points:
- The rule is generic, not dimension-only: `relayedFor` is a host-owned payload key on every mod append. With a stamp it is overwritten; without one (idle or event-driven appends) it is removed. No first-party mod appends today (V plan fact, `s1-build-plan.md:8`), so nothing existing changes.
- The row holds exactly what the mod was sent, because the same `pickRelayedFor` output feeds both. A mod not entitled to `hsid` and `turn` gets neither in its rows.
- Such a mod gets no `causes` either, because a turn ref is `turn:<hsid>/<n>` and would leak the session id (V `ids.ts:13`).
- `publisher gnomon` is the first-party test because the loader enforces it in both directions (V `manifest.ts:370-371`).
- GUI and CLI rows carry `principal`, `connId`, `surface` and no `causes`. The host knows no session for them (Aegis section 9). The live turn is a read-time join on seq against the attached session's turn rows, which §12.7 already describes for alignment (V `gnomon.md:200`).
- The mod SDK already forwards `p.relayedFor` to tool handlers. Only its type needs widening (V `gnomon-mod-sdk/src/runtime.ts:113-126`, by grep).

## Rulings, second set (2026-11-23): after Luna's S1.1 proposal and Aegis's design rulings

Source: `aegis-s1.1-design-rulings.md`, which binds. Where this differs from the draft above, this wins.

- **Colour, one behaviour per layer.** The shared validator refuses a failing colour with `colour-bad` (GUI and agent ops alike; never stored; `fix` may name a swatch). The picker calls the same function and offers the swatch. The renderer never trusts a row: a stored token failing the current check resolves to ink (line) or none (fill). The draft's `snapCustomColour` stepping is dropped.
- **Metric is OKLab** (Luna's threshold 0.06), not integer redmean: one implementation in `content-palette.ts`, sRGB linearisation from a literal 256-entry table, Lab quantised to integers before an integer compare, Luna's vectors (incl. 0.059 fail, 0.066 pass) and the night table run in Node, Chrome and WKWebView; a test that no second copy of the matrices exists.
- **Palette shape follows Luna:** per-role values (line, fill, text-on-fill), not `ContentSwatch {day, night}`; `nightOf` is her fixed transform. The neutral exemption applies to the line role only; a fill is tested against `text.primary` and `line.key-edge` with no exemption; an agent mark's dashed edge has at least 3:1 against its own fill.
- **Reserved list:** night `state.warn-bg` is the one named exception, with its composites computed in the test, not hardcoded.
- **Fold, unvouched rows (replaces the draft's fold rule):** a row with no well-formed `relayedFor` does NOT fold as human. `by.cls` gains a third value `unknown`, drawn dashed with no seal ("unknown hand"). Luna designs that state in S1.1.
- **Seal input** is the host-stamped `principal` plus `agent`, length-prefixed; never a nickname or tool input. Claimed sub-agent seals are NOT built in S1: there is no carrier for a self-claimed name and C2 forbids reading one from input. Revisit with the bridge in S1.4.
- **Dashed stroke** is derived in `dim-map` from `by`, never an element input.
- **Fallback stub** prefixes the kind with a fixed lead word; `dim_view` fences kind names as T3; the A13 fixture includes an approval-worded kind.
- **Open question carried to S1.3 (Aegis could not verify):** whether a `cli`-surface row can come from an agent's shell and so draw as human. Until settled, dimension write commands from the `cli` surface are refused unless the host knows the caller is human-class (extends C6).
