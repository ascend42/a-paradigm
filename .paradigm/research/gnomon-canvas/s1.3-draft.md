### Four findings the orchestrator should see first

1. **A command cannot write today.**
   - A command's effects are the union of the mod's tool effects (V `packages/gnomon/src/kernel/modhost/effects.ts:39-53`), and a manifest command has no effects field (V `kernel/manifest/manifest.ts:673`).
   - A mod with commands and no tools gets an empty set, so `state.get`, `state.set` and `log.append` are all refused `EFFECT` (V `modhost/host.ts:1002-1003`).

2. **`dim_view` and `dim_draw` are not legal manifest tool names.** Tool names must match `DOTTED_ID`, which has no underscore (V `manifest.ts:106,633`). A hyphen passes both that and the offer handoff pattern (V `gnomon-contracts/src/offer.ts:75`). Question F2.
3. **Rename has no carrier in `dim-shape:v1`.** The fold takes the title from the first start row only (V `gnomon-contracts/src/dim.ts:370`), and a new event kind would move `clientApiId` because `kinds: DIM_KINDS` is hashed (V `gnomon-contracts/src/client-api.ts:273`). Question F1.
4. **A top-level gesture param would move both ids.** The relay params are hashed into `modAbiId` and `clientApiId` (V `gnomon-contracts/src/rpc.ts:152-155`, `mod-abi.ts:165`). The proof rides inside `args`.

### 1. The mod `packages/gnomon-mods/dimension/` (id `gnomon.dimension`)

**Manifest** (shape of `workshop/gnomon-manifest.json`):
- `commands`: `dim.open`, `dim.attach`, `dim.op`, `dim.close`.
- `events`: the four `DIM_KINDS` and nothing else.
- `tools`: `dim-view` with `[read]` and `dim-draw` with `[read, write]`. Nothing can reach them: `callTool` has no caller until the S1.4 bridge (V `host.ts:83-85,900`).
- `requires`: `{ capabilities: [], egress: 'none' }`. No `log.read` capability is needed, because a mod principal already reads its own `modns` rows (V `kernel/socket/log-read.ts:148-152`). No views, keybindings or offers.

**Files:**
- `index.mjs`: the Workshop stdio loop (V `workshop/index.mjs:44-73`) plus a small mod-to-host request helper that echoes `callId`.
- `model.mjs`: pure, no I/O.
- `dim-shape.mjs`: generated. `build-dimension-mod.mjs` bundles `gnomon-contracts/src/dim.ts` and its three imports (V `dim.ts:22-24`) with esbuild as ESM, unminified, LF, path comments stripped. It is committed, and a test rebuilds it and compares bytes.
- Windows trap: build from forward-slash paths and compare after LF normalisation is already guaranteed by `.gitattributes`.

**The single entry (A6):**

```js
// model.mjs
export function actorOf(relayedFor)   // {cls:'human', principal} only when surface === 'gui' and no agent key; else null
export function apply(state, ops, actor)  // → { ok, refused, secret, next }  (validateDimOps, then foldDimRow on a synthetic row)
export function titleProblem(title)   // length ≤ DIM_LIMITS.title, no \p{Cc}\p{Cf}\p{Zl}\p{Zp}, no secret after dimTextForScan
export function grantDefault(state, hsid) // first attached hsid: on; any later one: off (pure; consumed in S1.4)
```

- `command.run` and `tool.call` are thin callers of `apply`.
- In S1.3 `tool.call` always answers `{refused: 'not-available', saw: [<names of relayedFor fields received>]}` and appends nothing. `saw` holds field names only. It exists so the first-party identity test can observe the stamp.
- The mod never reads identity from `args` or `input` (C2).

**Commands** (`hsid` and `repo` are host-composed, see point 3):

| Command | Args | Behaviour |
|---|---|---|
| `dim.open` | `{dim, title?, opened}` | Unknown `dim`: create (needs `title`, checked by `titleProblem`) and append `session.start{v, dim, title, attached:[hsid], opened}`. Known and attached: append a start row (a reopen). Known and not attached: refuse `not-attached`. Result `{dim, firstSeq, seq, hash: dimHash(state)}` |
| `dim.attach` | `{dim}` | Needs `args.repo` equal to the dimension's recorded repo, else refuse `repo-mismatch`. Appends `attach{v, dim, hsid}` |
| `dim.op` | `{dim, ops}` | `apply`. On any secret or zero accepted ops: no row. Otherwise one row `op{v, dim, ops: ok}`. Result `{seq, refused}` |
| `dim.close` | `{dim}` | Appends `session.end{v, dim, ops, nodes}` |

**Hostile validation, whatever the GUI checked:**
- every command refuses unless `actorOf(relayedFor)` is non-null;
- `dim` must match `DIM_ID_PATTERN`; `opened` must be in `DIM_OPENED`;
- ops go through `validateDimOps` only, so `lock`, `unlock` and `clear`, unknown kinds and fields, and a `by` or `relayedFor` key are refused (V `dim.ts:707-712`);
- the payload is built only from `validation.ok`, which are `copyJson` copies with prototype keys dropped at any depth (V `dim.ts:258,863`);
- refusals carry codes and fixed sentences, never input.

**State and keyframes** (limits: 64 KiB per value, 1 MiB total, V `modhost/state.ts:24`):
- `idx:<ulid>` holds `{repo, firstSeq, lastSeq, title}` and is written on every append. Cap 512 dimensions.
- `kf:<ulid>` and `kf:<ulid>:<i>` hold a keyframe in chunks of at most 60 KiB with `{seq, hash}`. Written at `dim.close` and every 256 ops, for the 4 most recent dimensions, and skipped above 256 KiB.
- Cold open: load the keyframe and verify its hash, then page `kernel.call{log.read}` with `since: kf.seq`, `until: idx.lastSeq` and the four kinds. Without `until`, a page scans up to 10,000 unrelated rows (V `log-read.ts:53`).
- The in-memory fold uses `foldDim` only.

**Pin:** add the tree hash to `FIRST_PARTY_PACKAGE_HASHES` (V `install.ts:111-124`). The `SUPERSEDED` table is untouched. `mods-admin` lists the mod from the folder with no change (V `modhost/mods-admin.ts:212-257`).

### 2. The GUI gesture proof for `mod.command`

**What §11.5 requires.** "The GUI never calls a write verb without a user gesture" (`G-GUI-04`, a `#gui` falsifier).

**What exists.**
- Every other GUI write is `log.append{request.*}`, gated by class human plus the gui or device credential, with `isTrusted` checked in the page (V `dispatch.ts:949`, `ui/app.ts:598`).
- `mod.command` from the GUI is refused outright (V `dispatch.ts:923-925`).
- The wrapper has no page IPC, so a native attestation is not available.

**Honest limit.** No design lets the kernel verify a human press made in a web page. Resistance to script running in the page is nil. It rests on the unchanged CSP, the pinned bundle and the absence of mod code in the page.

**Smallest sound design.** A fail-closed stamp plus one sender.

GUI, `core/gesture.ts` and `core/mod-command.ts`:

```ts
export type GestureKind = 'pointer' | 'key' | 'paste' | 'menu';
export interface Gesture { readonly n: number; readonly kind: GestureKind; readonly at: number }
export function gestureOf(e: { isTrusted: boolean; type: string; repeat?: boolean }, now: number): Gesture | null;
export function sendModCommand(c: Pick<GnomonClient,'call'>, g: Gesture | null, name: string, commandId: string, args: Record<string, unknown>): Promise<unknown>;
```

- `gestureOf` returns null unless `isTrusted` and the type is one of `pointerup`, `keydown`, `click`, `paste`.
- `n` is a module-private counter.
- `sendModCommand` sends nothing when `g` is null, older than 10 s or used 4 times. It adds `args.gesture = {n, kind}`.
- The board leaf attributes an engine edit to the last trusted event on the board. With none in the last second, the edit is dropped and rolled back.

Kernel, `socket/gesture.ts`, called where `dispatch.ts:923` refuses today:

```ts
export const GESTURE_FANOUT = 4;
export function takeGesture(conn: { gesture?: { n: number; used: number } }, args: unknown): Record<string, unknown>;  // returns args without `gesture`
```

- Refuses `FORBIDDEN gesture` unless the class is human, `args` is a plain object, `gesture.n` is a safe integer of at least 1, and `kind` is in the closed list.
- `n` above the connection's last one resets `used`; `n` equal to it is allowed while `used < 4`; a lower `n` is refused. That is replay resistance within the connection.
- The key is stripped, so no mod sees it.
- `dispatch.ts:689` then reports the relay as available.

**Tests:**
- kernel: missing, repeated past the fan-out, decreasing, malformed; the key never reaches a probe mod;
- GUI unit tests of the token rules;
- a static test that the literal `'mod.command'` occurs in `gnomon-gui/src` only in `core/mod-command.ts` and `preview/fake-kernel.ts`;
- a browser test where a synthetic `dispatchEvent` draw sends zero frames.

### 3. Human-only writes (C6) and the `cli` surface

**How the host knows.** `relaySurfaceOf` gives `gui` or `cli` only to the human class (V `dispatch.ts:232-235`). `relayCommand` receives the surface and, today, drops the class (V `host.ts:879-882`).

**New generic host rule** (replaces a per-mod table): a relayed command whose stamp lacks `surface: 'gui'` runs with effects capped at `read`.
- `CallContext` command gains `cap?: 'read'`, and `effectsFor` intersects it, as the dev cap does (V `effects.ts:51`).
- An agent, session, voice or mod caller, and a human on a device key, can then never `log.append` or `state.set` through any mod's command.
- The mod also refuses first with a plain message (point 1). The host cap is the guard.
- No first-party mod uses commands today, so nothing breaks (I, from plan fact 8).

**A CLI-surface write** is refused by the mod (`not-human-gui`) and would be refused `EFFECT` by the host. `gnomon dim replay` and `gnomon dim stats` need no relay: they read the verified log as `gnomon desk stats` does (V `cli/desk-cli.ts:82-84`).

**Host-composed args.** New `#composeRelayedArgs` in `host.ts`, beside `#composeRelayedInput` (V `host.ts:828-846`):
- strips `HOST_INPUT_KEYS` from client args;
- when the client names `focus:{hsid}` and `#mayJoin` passes (V `host.ts:854-861`), sets `args.hsid`;
- for a `gnomon`-published mod only, sets `args.repo` from a new `ModHostOptions.focusRepo(hsid)` port. That is the repo scope `repo:<16 hex>`, never a path.

**Row scope.** `CallStamp` gains `scope?: {repo}`; `ModAppendRow` and the daemon append pass it on (V `daemon.ts:1344`, `kernel/log/kernel-log.ts:339`). "Listed by repo" is then a read filter.

**Write grants per hsid.** S1.3 builds the attach row and the pure `grantDefault`. The revocable override needs a carrier (mod state, or a new kind that would move `clientApiId`), and nothing reads it before S1.4, so it is decided there.

**GUI rows after a second attach.** `dimHsidOf` returns null for a GUI row once two sessions are attached (V `dim.ts:296-301`). `gnomon dim stats` takes the session from the nearest preceding start or attach row instead.

### 4. C8: paste and drop before the engine

In `src/board/index.ts`, replacing the report-only hook (V `index.ts:281-319`):
- **Per-board listeners on `document`, capture phase.** They act only when the event target or `document.activeElement` is inside this host. They are removed at unmount, which also closes the "per-board refusal listeners" carry-over.
- **Paste, target is the engine's text-edit textarea:** `stopImmediatePropagation` only. A textarea takes plain text natively, and the text reaches the log at commit, through the validator.
- **Paste, anything else:** `preventDefault` and `stopImmediatePropagation`, always.
  - Files present: refuse.
  - No `text/plain`: refuse.
  - Otherwise the handle emits `onPasteText(text)`, and the leaf builds one `add` op of kind `text` at the view centre. Text over `DIM_LIMITS.text` is refused with a line.
  - The text is never parsed, so SVG source and engine JSON become literal text.
- **Copy and cut:** the leaf keeps an in-memory register of the selected nodes and writes their plain text to the system clipboard. A paste whose text equals the register's adds clones with new ids, offset 16. `by` is whoever pastes; nothing else is carried.
- **Drop:** every drop stays refused (V `index.ts:299-310`).
- The `paste-types-filtered` patch stays as a second line.

**Test `gnomon-gui/test/board-c8.test.ts`,** real Chrome over the DevTools protocol, using the real-paste mechanism of commit 97f2ae82. Each case expects zero CSP rows, no `iframe` or `img` under the host, no element of type image, iframe or embeddable, the handle alive, and either exactly one new text node equal to the pasted text or a refusal line. Cases:

### 6. The live loop

- **Read path.** The GUI already follows the whole log into its store (V `core/client.ts:276-296`). `core/dim-store.ts` keeps each dimension's rows, an in-memory keyframe every 512 rows, `stateAt(dim, seq?)` built with `foldDim(rows, seq, keyframe)`, the list by `scope.repo`, and the last dimension per hsid.
- **Write path.** Engine edit, then `onEdit(ops)`, then `dim-live.local(ops, gesture)`, then `sendModCommand('gnomon.dimension', 'dim.op', {dim, ops, focus:{hsid}})`, then the mod, then the row, then the subscription, then the store, then `handle.render`.
- **`core/dim-live.ts`** is a pure controller with events `local`, `ack`, `row` and `timeout`:
  - `view()` is the confirmed fold plus pending batches as synthetic rows stamped as me.
  - One send is in flight per dimension; queued batches coalesce up to 64 ops.
  - A batch is confirmed when the row with the acked `seq` arrives.
  - A refusal, or no ack and no row within 8 s, drops the batch, re-validates later pending batches against the new view (dropping those that now fail), re-renders, and raises one toast naming the field and code. A mark never vanishes silently (Mika's open item 2).
- **Kernel link down** (Mika's open item 1): the keep line reads "not saved · reconnecting", the rail is disabled, and pending batches roll back at the timeout. There is no offline queue in S1.3.
- **Drags.** `onEdit` fires at pointer-up, and `elementsToOps` emits one `move`.
- **Undo.** `core/dim-undo.ts` exports `invertDimOps(before: DimState, ops: DimOp[]): DimOp[]`:
  - add inverts to delete; update to an update with the prior values (null for absent keys); move to the negated move;
  - delete inverts to an add with a new id, because ids are never reused (V `dim.ts:727`), plus updates of `from`, `to` and `parent` that pointed at the old id.
  - Cmd+Z in the leaf sends the inverse through the same path.
  - Engine history is bypassed: `undo` and `redo` leave the `key-actions-allowlist` and `api-run-action` patches (two counted-patch edits).
- **Reconnect.** The store resumes from its cursor, and `dimHash(stateAt(dim))` must equal the `hash` of the next `dim.open` result.
