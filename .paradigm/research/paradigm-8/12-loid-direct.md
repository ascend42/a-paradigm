# Loid — direct view on the 8.0 decisions (2026-10-15)

Correction: earlier boards attributed shape/feed positions to Loid; 06 took none. These are her stated positions.

1. Shape (Heddle + Shuttle): FOR, on one condition — the loop reads only the kernel log, never the Shuttle display. One ledger + one identity (hsid) + one scheduler fixes today's leak (injections, verdicts, outcomes in stores that never join).
2. Socket-only band: NEUTRAL, leaning for — files-first would have been a second unauthenticated record drifting from the log. Risk is timing: if the Mod-socket spike fails the band slips; tie learning work to move 1 (the log), not move 3.
3. Three oracles in 8.0: FOR — the most important learning decision; a key-proven reviewer is the attributed verdict source the loop never had (6 founder verdicts ever). Caveats: calibrate the reviewer (track passes that later break in the field; 200/200 debates and 5/5 certifications show an uncalibrated reviewer passes everything); agents claim, only the kernel logs certification.
4. Six laws: FOR all six. Honesty CI covers learning metrics too (appliedCount is a number without a denominator). "Spends nothing by default" → deterministic tend passes (dedupe, decay, source-hash) run on log-derived triggers; the LLM contradiction judge and teacher drafting each take a budget permit; budget denials logged as learning signal. "Reversible" includes learned state: uninstall leaves notebooks and ledgers intact or explicitly exports them.
5. Day-one internal logs, all joinable on hsid + turn + contractId + entry id: injection receipt (entries offered, tier, source_hash, frozen slice); credit (turn outcome accepted/revised/dismissed linked to injected entries); oracle results under the kernel's key per node with reviewer identity; detector events (test/tsc failure after edit, KNOT/refusal, thrash flag); loop-ledger row per iteration; budget reserve/deny/usage; tend digests + fate of each proposal; decay write-backs and contested tags; founder verdicts. Every learning number keeps its denominator (offered, credited, broke).
6. Warpline opt-in: NEUTRAL with a firm rule — calibration keyed by (repo, mode), never pooled; a clean git merge + CI is not the same verdict as a Warpline admission. Git-mode still grows the credit denominator; the KNOT denominator stays thin and the per-codebase moat accrues only in Warpline projects. Log git conflicts as contested/uncontested counts so a repo adopting Warpline later has a baseline.
7. Missing from the plan:
- No decision defines "credit" or ships the injected/credited split.
- Injection dark since 2026-07-22; 8.0 must re-enable it with credited ranking, not popularity.
- Liveness falsifiers (≥1 verdict per working day, ≥1 tend per week) and week-4 targets from 06 §6 are not gates yet.
- Nothing calibrates the reviewer oracle.
- The refute step has no teeth (all certifications survive).
- The loop's real input is founder time: something must put pending verdicts and tend proposals in front of the founder (the band, once the socket works).
- Nobody consumes the outputs: every digest needs a reader that acts on it.
