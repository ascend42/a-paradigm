## 3. Migration risk (Jinx perspective)

**Cohort breakdown for projects upgrading 6.0.3 → 6.0.4:**

| Cohort | Predicate | Behavior change | Impact |
|---|---|---|---|
| A | `roster includes 'compliance'` | None | Zero risk |
| B | `!includes('compliance') && no ~aspect anywhere` | None — Check 6 short-circuits, Check 10 drift = 0 | Zero risk |
| **C** | `!includes('compliance') && exists ~aspect line` | **Silent loss of drift-block + advisory** | **Real risk** |

**One-time migration notice — ship it.** Triggers on first paradigm CLI invocation matching cohort C predicate AND no `.paradigm/.v6-0-4-migration-acknowledged` marker:

```
[paradigm 6.0.4] Enforcement model changed.

This project defines ~aspects but has no compliance-archetype agent on
the roster. Previously, the Stop hook blocked on aspect drift. As of
6.0.4, the framework no longer enforces aspect coverage in absentia.

Run `paradigm shift` to nominate Rune (compliance) for this project, or
ignore this notice to opt out of aspect enforcement.

This message will not appear again.
```

Implement as `migration-notices.ts` invoked from `packages/paradigm/src/index.ts`. Must not break `paradigm --version` / `paradigm --help`. Write marker after first emission.

## 6. paradigm shift nomination UX (Helix perspective)

**Surface: `paradigm shift` only at v6.0.4.** Not preflight (per-session = noisy). Nomination is project-config decision, runs at setup/upgrade cadence.

**Prompt copy (TTY interactive):**

```
Step 2c-nominate/6: Symbol enforcement

  This project defines ~aspects but no compliance-archetype agent
  (Rune) is on the roster.

  Without a claimant, paradigm 6.0.4 no longer enforces aspect
  coverage. You can:

    [Y] Add Rune (compliance) to the roster — recommended
        Authority defaults will be written to .paradigm/authority.yaml.
        Default mode: advise (Rune surfaces findings, never blocks).

    [N] Skip — opt out of aspect enforcement for this project
        This decision is remembered. Re-run with --force to revisit.

  Add Rune to roster? [Y/n]:
```

**Default key Y** (Enter accepts) — aligns with TD-2026-04-26-284 advise default.

**Non-TTY (`!process.stdin.isTTY`):** skip silently, write skip marker. Never auto-Y in CI.
**`--no-prompt` flag:** explicit skip equivalent.
**`--force`:** clears skip marker so prompt re-fires (matches existing shift convention at lines 164, 352).

## 7. Learning-loop hook (Loid perspective)

**Data continuity confirmed.** Three signals stay live regardless of roster:

1. **`compliance-history.jsonl`** at lines 873-886 of paradigm-common.sh — **unconditional**, one row per Stop-hook run. Critical to preserve. This is Loid's primary observability surface for absent-Rune.
2. **Drift count via `paradigm compliance-check`** — Node-side computation runs unchanged. Only emission gated. DRIFTED_COUNT still flows to JSONL.
3. **Coverage ratio via `paradigm doctor`** — new line item exposes ratio for any consumer (ambient pass, manual inspection).

**Loid's nomination signal (manual path at v6.0.4):** her postflight pass (`paradigm ambient postflight`, paradigm-stop.sh:114) reads `compliance-history.jsonl`. If she sees 5+ sessions with violations=0 + elevated implicit drift (component-count delta without aspect updates, derivable from `.paradigm/scan-index.json` snapshots) AND no compliance archetype rostered → emit nomination via existing `.paradigm/events/nominations.jsonl`. User sees on next `paradigm status`.

**Honest gap:** richer per-component snapshot (v6.2 plan line 74) does NOT ship at v6.0.4. Existing JSONL has aggregate counts only. Loid can detect "drift increasing" but cannot identify *which* components drifted historically without re-walking scan-index. v6.1 closes this.

**No new code path required at v6.0.4.** Existing snapshot writer suffices. Confirm code review preserves lines 873-886 — they are NOT part of the de-enforcement scope.
