## 1. Executive summary

v6.1 closes the loop opened by v6.0.4. v6.0.4 took the framework's hands off symbol enforcement; v6.1 puts the tools into the agents' hands so "agent-owned" stops being rhetoric (TD-2026-04-25-417). It is a cohesive package, not a polish release.

**Six work-streams ship together:**
1. Soft-block primitive (`paradigm_propose_block`) — load-bearing, all other authority work depends on it
2. Authority MCP tools (`paradigm_authority_claim`/`_release`) reading the schema shipped at v6.0.4
3. Hook-orchestrator TS module (`paradigm_hook_dispatch`) — bash hooks become shims
4. Tier-split implementation per `tier-split-design.md` (substrate already on disk; mostly wiring)
5. Sovereign notebooks + cross-references per TD-2026-04-25-704 (5-kind taxonomy, schema `v0-experimental`)
6. Failure Ledger primitive (punted from v6.0.3) + Rune's six pre-seeded tier-1 notebook patterns + four new Rune MCP tools + `compliance-check` → `aspect-report` rename + session-start ambient pass

**Headline scope:** ~3 sprints, ~6-8 weeks calendar (including soak between sprints, release per sprint).

**Headline risks (Jinx):** soft-block override-storm, hook-orchestrator parity gap, tier-1 promotion poisoning, schema lockstep with `@a-company/agent-format`, scope creep pulling v6.2 forward.

**What ships in v6.1:** the six work-streams above.
**What defers further (v6.2+):** `paradigm_optout_register`, `paradigm_severity_emit`, JSONLogic unblock predicates, override-cluster auto-coaching, always-on per-component metric snapshot to lore, auto-promote tier-1 (manual confirm only at v6.1).

**Load-bearing fork:** soft-block primitive is the trunk. Authority claim/release tools, hook-orchestrator, all four new Rune tools, and the session-start ambient pass all consume `paradigm_propose_block` semantics. If soft-block slips, the whole authority axis slips.

**Parallel-safe:** tier-split + cross-refs schema can run alongside soft-block from day one (both are notebook-domain; neither reads remediations). They MUST merge before the notebook MCP surface stabilizes (Sprint 2 close), because `paradigm_notebook_add` will gain both a `tier:` parameter and a `refs:` parameter in the same call.

**Failure Ledger** is independent of soft-block but light-touch — slot into Sprint 3.

**Independent of everything:** `compliance-check` → `aspect-report` rename (data-only, alias kept one minor). Can ship in any sprint. Recommend Sprint 3 to bundle with the new Rune MCP tools.

## 3. Sprint breakdown

Three sprints. Each ends with a release on main (per main-branch convention: every push is a release).

### Sprint 1 — Soft-Block Primitive + Authority MCP Tools (~2 weeks, releases as 6.1.0-rc.1 or 6.1.0)

**Scope:**
- `paradigm_propose_block` MCP tool: agent-initiated, framework-honored, user-keystroke-overridable. Writes `.paradigm/remediations/<id>.yaml` (schema: id, claimant agent, severity, reason, unblock_hint, created, optional `expires_at`). Stop hook (still bash at this stage) reads `.paradigm/remediations/` and refuses-with-override if any active record present.
- Override mechanism: user keystroke (e.g., `paradigm override <id>` or env var `PARADIGM_OVERRIDE=<id>`); records to `.paradigm/events/overrides.jsonl` for Loid calibration.
- `paradigm_authority_claim` / `paradigm_authority_release` MCP tools — read/write `.paradigm/authority.yaml` (schema locked at v6.0.4 per `v6.0.4-implementation-plan.md` §2).
- Migration-notice for cohort C projects: when first authority claim or block fires, log Loid-visible event.

**Agents:** Builder (Kit) for MCP tools + bash hook integration; Architect for spec; Jinx for stress-test (override storm scenarios); Loid for calibration-event format; Documentor for CLAUDE.md update on `paradigm_propose_block`.

**Deliverables:**
- `packages/paradigm-mcp/src/tools/propose-block.ts`, `authority.ts`
- `.paradigm/remediations/` directory + reader util in `paradigm-common.sh` (~30 lines POSIX)
- `paradigm override` CLI command in `packages/paradigm/src/commands/override.ts`
- `packages/paradigm/test/propose-block.spec.ts` + override storm test
- CLAUDE.md update: agent prompts now learn how to call `paradigm_propose_block`

**Estimate:** ~10 working days.

**Scope-creep risk:** moderate. Resist pulling JSONLogic unblock predicates forward (v6.2). Plain-string `unblock_hint` only at v6.1.

## 7. Loid's calibration scope

### What v6.1 enables that Loid couldn't do before
1. **Override-cluster detection** — soft-block writes to `.paradigm/events/overrides.jsonl`. Loid reads pattern: ≥3 same-rule overrides within 14 days = nominate notebook exception (Rune's `directory-exception-patterns` notebook auto-extends). v6.1 implements detection + nomination; auto-coaching loop is v6.2.
2. **Notebook promotion candidacy** — Loid runs end-of-session pass: scans tier-2 entries, scores cross-project-confirmation + applied-velocity + content-generality + confidence. Writes `.paradigm/notebooks/_loid-digest.yaml`. Surfaced via `paradigm doctor` and session-start digest. Manual confirm only at v6.1 (auto-promote v6.2 when ≥3 projects of data exist).
3. **Cross-ref unresolved patterns** — Loid counts unresolved refs per session by target. ≥5 unresolved on same target → nominate cross-ref refactor (target lifts to standalone tier-1, or referent agent should be rostered).
4. **Failure-ledger learning** — read API over `.paradigm/events/failure-ledger.jsonl`. Loid surfaces failure clusters (same agent, same failure_kind, ≥3 instances) as candidate notebook entries.
5. **Authority-claim audit** — read `.paradigm/authority.yaml`; identify drift between archetype-default claims and project-specific overrides. Surface "Rune is in Guard mode here but Advise everywhere else" as informational.

## 8. Migration story

### Silent (no user action required)
- `compliance-check` continues working via alias for one minor (warning emitted on first call per session)
- `compliance-history.jsonl` continues to be read; new writes go to `aspect-report-history.jsonl` (Loid reader hits both)
- Notebook entries with no `scope:` field continue to default to `project-specific` (tier-2) — backward compat per tier-split-design §1
- Hook-orchestrator off by default (Sprint 3 feature flag, opt-in); bash hooks continue working
