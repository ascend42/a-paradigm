# v6.1 Implementation Plan — Sovereign Notebooks + Cross-References

**Drafted:** 2026-04-25 by main session synthesis (architect + Loid + Jinx parallel critique).
**Status:** design locked; implementation deferred to dedicated session(s).
**Schema:** `v0-experimental` — explicit migration path documented per Jinx's prudence.

---

## Thesis

v6.0.3 reserved `share_notebooks` for content-injection runtime. v6.1 ships **a different primitive** that achieves pair-learning signal without sovereignty cost: **disjointed notebooks linked by structured cross-references**. Each agent's notebook stays their own viewpoint; entries reference partner entries via labels (never inlined content); the learning loop reads the link graph instead of merged content.

Loid (who designed share_notebooks at v6.0.3) explicitly reversed her position during the v6.1 critique pass: *"I was wrong to settle for `[from: X]` — sovereignty by construction beats attribution by annotation."* That's the strongest signal that cross-refs is the right primitive — the agent who owns the learning loop changed her mind based on user reframe.

## What ships at v6.1 (locked)

### 1. Cross-references primitive (`#cross-refs`)

**Field shape on notebook entry:**
```yaml
id: e7
notebook: nb-cross-package-mn53xf98
agent: reviewer
content: "..."
confidence: 0.72
symbols: [#schema, #partners]
refs:                                   # NEW — outbound cross-references
  - target: "architect/nb-monorepo-mn53wvzd#e3"
    kind: builds_on
    note: "Builds on architect's partners-schema framing"
inbound_refs_cached:                    # populated by indexer, read-only
  - source: "scholar/nb-habits#e12"
    kind: corroborates
    last_seen: 2026-04-25T...
schema: v0-experimental
```

**Ref-kind enum (5 — Architect's taxonomy, user pick):**
- `agrees` — corroboration / convergent finding
- `diverges` — different conclusion from same evidence
- `supersedes` — replaces or invalidates target
- `builds_on` — extends target's framing
- `see_also` — neutral cross-reference

User chose Architect's 5-kind over Loid's 4-kind (grounds-in/corroborates/contradicts/extends) and Jinx's 0-kind. Trade-off accepted: kinds are designed under N=1 pair condition; v6.2 may add or migrate values based on observed usage.

**Sovereignty invariant (HARD):**
- Content NEVER inlined into another agent's prompt
- Refs render as labels only: `[ref: scholar/L-2026-04-25-001 (builds_on)]`
- Entry IDs immutable post-promotion (mirrors lore tombstone pattern)
- Reverse-edges computed at index time; never auto-mutate target entry file

### 2. Three discovery affordances (user pick: all three)

**(a) Explicit search tool:** `paradigm_notebook_search --partner=<id>` — on-demand pull.

**(b) Session-start partner activity digest:** When session begins for agent A, list A's partners' last 5 entry titles (Jinx's "card catalog" answer).

**(c) Debrief candidate-refs report:** Loid surfaces "partner has N unlinked entries touching your symbols" at debrief end (max 3 per turn).

All three are complementary surfaces, ~20 lines each. Together they solve the "library with no card catalog" risk Jinx flagged without breaking sovereignty.

### 3. Stale-reference handling

Entry deletion → soft tombstone (entry stays with `status: retracted`, body replaced with retraction reason). Cross-refs to retracted entries render as `[ref: agent/L-... (retracted YYYY-MM-DD)]`. Pattern mirrors lore redirect envelope (post-Bundle A, v6.0).

### 4. Caps + invariants

- Max 5 outbound refs per entry
- Max 3 inbound refs surfaced per debrief turn
- Ref requires local content ≥ 50 tokens (no empty pointer entries)
- Ref kind must be one of the 5 enum values; reject free-text kinds
- `note:` field is free-text but capped at 200 chars

### 5. Pair-coherence telemetry (observability-only at v6.1)

`.paradigm/_pairs/{a-b}/coherence.yaml` weekly rollup:

```yaml
pair: scholar-educator
ref_count: { outbound_a_to_b: 12, outbound_b_to_a: 8 }
ref_kinds: { agrees: 7, builds_on: 9, diverges: 3, supersedes: 1, see_also: 0 }
bidirectional_promotion_rate: 0.34
pair_acceptance_delta: +0.08
asymmetry_index: 0.20
stale_ref_rate: 0.05
```

**v6.1 stance: gates NO behavior on these metrics.** Loid was clear — designing thresholds with N=1 data is the same trap as the original ambient-threshold spam. Metrics surface in `paradigm:health` for observation; v6.2 introduces gating once data exists.

### 6. share_notebooks deprecation (Loid's middle-ground)

- Field schema preserved on `PartnerRef`
- Only valid value at v6.1: `'off'` (default)
- `'read'` and `'read-write'` → deprecated, emit warning, no runtime effect
- Schema reserved for possible v6.2+ revival if cross-refs prove insufficient

### 7. Failure Ledger primitive (independent of partners work)

Sage's structured failure-ledger from v6.0.3 punt list. Ships alongside cross-refs as separate concern. Spec deferred to its own design pass.

### 8. CI drift detector

Pulled forward from v6.2. Detects drift between `adoptions.yaml` declared scopes and runtime behavior. Protects cross-refs and partners surfaces from silent regression.

### 9. Symphony fixes

Per `docs/specs/conductor-symphony-fixes.md` (separate from Conductor 16-bug list). Bundle into v6.1.

## Back-compat surface

v6.0.3 → v6.1 migration is additive:
- `share_notebooks: 'off'` continues to work; `'read'`/`'read-write'` start emitting deprecation warning but keep current no-op behavior
- New `refs[]` / `inbound_refs_cached[]` fields default to undefined → empty arrays
- Existing notebooks unchanged at storage; indexer populates `inbound_refs_cached` lazily
- `paradigm shift`: existing partners with `share_notebooks: 'read'/'read-write'` get auto-migrated to `'off'` with one-time prompt to reconfigure

Major callout in CHANGELOG: v6.1 is "schema additive, semantics deprecation" — no breaking changes, but `share_notebooks` non-`'off'` values are on a deprecation path.
