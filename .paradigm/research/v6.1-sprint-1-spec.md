## 2. Remediation YAML schema

**Path:** `.paradigm/remediations/<id>.yaml`
**Archive path:** `.paradigm/remediations/.archived/<id>.yaml`

```yaml
id: rmd-mn7k2x9                  # rmd-<base36-of-Date.now()>, ~8-9 chars total
claimant: compliance              # archetype id (NOT agent-instance id)
severity: guard                   # advise | auto-author | guard
reason: |                         # free-text, multi-line allowed
  #payment-form has no aspect anchor; imports stripe → suggested ~payment-pii
unblock_hint: |                   # PLAIN STRING at v6.1 (JSONLogic deferred to v6.2)
  Add ~payment-pii anchor to packages/web/src/components/payment-form/.purpose
  OR run: paradigm aspect stub-create rmd-mn7k2x9
created: '2026-04-27T20:30:00Z'   # ISO 8601 UTC
expires_at: '2026-04-27T22:30:00Z'  # OPTIONAL — when present, Check 14 skips after this timestamp
target:                           # OPTIONAL — context surfaced in block message
  file: packages/web/src/components/payment-form/index.tsx
  symbol: '#payment-form'
  line: 42
```

**Severity vocabulary — v6.1 honors only `guard` as a hard block:**

| Value | v6.1 behavior | v6.2 future |
|---|---|---|
| `advise` | Stderr advisory line; exits 0 (informational only) | Same |
| `auto-author` | Stderr advisory + framework hint that the claimant agent should auto-author the fix | Auto-author MCP tool wired |
| `guard` | **Hard block** — stop hook exits non-zero with stderr block message | Same + Guard mode policy enforcement |

**Vocabulary collision note:** `authority.yaml`'s severity vocab is `{advise, warn, block}` — that's the **policy stance** the claimant operates under (project-wide config). The remediation's severity vocab is `{advise, auto-author, guard}` — that's the **block intent for this single event**. **Do NOT unify these at v6.1.**

**ID format:** `rmd-<base36-Date.now()>`. Reference impl: `'rmd-' + Date.now().toString(36)`.

## 4. Stop hook Check 14 logic — paradigm-common.sh

**Numbering decision:** append as Check 14 (NOT renumber existing 11/12/13). Header comment lines 19-33 add line: `#  14. Active remediations from agent-authored .paradigm/remediations/ (v6.1)`.

**Pseudocode (POSIX sh — Builder writes literal):**

```sh
# --- Check 14: Active remediations (v6.1 soft-block primitive) ---
if command -v paradigm >/dev/null 2>&1; then
  _REMEDIATIONS_JSON=$(paradigm internal active-remediations --json 2>/dev/null) || _REMEDIATIONS_JSON="[]"
else
  _REMEDIATIONS_JSON="[]"
fi

_OVERRIDE_LIST="${PARADIGM_OVERRIDE:-}"

# Iterate using temp file to preserve VIOLATION_COUNT (subshell-safe)
echo "$_REMEDIATIONS_JSON" > /tmp/.paradigm-rmds-$$
# Builder writes the actual iteration; key behaviors:
#   - For each id: check if in $_OVERRIDE_LIST → write override event, skip
#   - severity=guard → block (VIOLATION_COUNT++)
#   - severity=advise|auto-author → advisory line only
rm -f /tmp/.paradigm-rmds-$$
```

**Critical subtleties:**
- `expires_at` filtering happens in the **TS helper**, NOT in bash.
- The `.archived/` subdirectory is **never read** by Check 14.
- `while read` in a piped subshell won't propagate VIOLATION_COUNT; use temp file.
- Missing `paradigm` binary → empty JSON → no block (graceful degradation).
- Missing `.paradigm/remediations/` dir → helper returns `[]` → no block.

## 5. paradigm override CLI semantics

**Subcommands:**

```
paradigm override <id>                  # Clear single remediation by id
paradigm override list                  # Show all active remediations
paradigm override clear-all --force     # Bulk clear (requires --force flag)
```

**`paradigm override <id>`:**
1. Read `.paradigm/remediations/<id>.yaml`. If missing → error: `Remediation rmd-XXX not found.` exit 1.
2. Stamp `archived_at: <ISO ts>` field onto the YAML.
3. Move file to `.paradigm/remediations/.archived/<id>.yaml` (audit trail).
4. Append override event to `.paradigm/events/overrides.jsonl` with `mechanism: cli`.
5. Print: `Override recorded → .paradigm/events/overrides.jsonl` and `<id> cleared. Re-run your blocked operation.`
6. Use `cli-output.ts` helpers (`success()`, `dim()`).

**`paradigm override list`:**
- Read `.paradigm/remediations/*.yaml` (top-level glob).
- Render table: id | claimant | severity | created (relative time) | reason (first line, truncated 60 chars).
- Empty state: `No active remediations.` via `dim()`.

**`paradigm override clear-all --force`:**
- Without `--force` → error and exit 1.
- With `--force`: iterate, archive each, append one event row each.

**`paradigm internal active-remediations --json`** (helper, hidden command):
- Read every `*.yaml` in `.paradigm/remediations/` (not `.archived/`).
- For each: parse YAML; if `expires_at` is set and is in the past, skip.
- Output: JSON array of `{id, claimant, severity, reason, expires_at, created}`.
- Errors silently → emit `[]`.

## 7. Authority MCP tool semantics

**Single-claimant-per-scope model.** The existing v6.0.4 schema keys claims by `scope` name. Multiple claimants per scope is NOT supported at v6.1 — re-claiming overwrites.

**I/O routing — both MCP tools consume reader/writer functions in `core/authority.ts`** (do NOT re-implement YAML I/O).

**Idempotency:**
- `claim`: read → merge claim onto `claims[scope]` with `source: 'explicit'`, `since: now()` → write. If scope existed with `source: 'archetype-default'`, overwrite (explicit takes precedence).
- `release`: read → delete `claims[scope]` → write. If scope absent, no-op (returns `released: false`).

```markdown
## Agent-Owned Soft-Blocks (v6.1)

When you (an archetype agent — Rune, Aegis, Jinx, etc.) detect a condition
the user should resolve before continuing, call `paradigm_propose_block`.
The Stop hook reads `.paradigm/remediations/` and will refuse-with-override
on your next run if `severity: guard`.

**When to call:**
- Coverage drop on a tracked aspect (Rune)
- Missing portal gate on a new endpoint (Aegis)
- Symbol drift you cannot auto-heal (Rune)
- Edge case the user agreed to handle but hasn't (Jinx)

**Do NOT call for:**
- Things you can fix yourself
- Things only the user can decide and that don't block correctness (use a wisdom note)
- Nag-loops on the same scope (cap at one active remediation per concern)

**Severity guidance:**
- `advise` — informational stderr line, no block
- `auto-author` — same as advise at v6.1; signals you intend to author the fix
- `guard` — hard block. Use sparingly.

**Example invocation:**

Rune detects #payment-form imports stripe but lacks an aspect:

paradigm_propose_block({
  claimant: 'compliance',
  severity: 'guard',
  reason: '#payment-form imports stripe → suggested ~payment-pii aspect',
  unblock_hint: 'Add ~payment-pii to packages/web/src/components/payment-form/.purpose, OR run paradigm aspect stub-create rmd-<id>'
})

The user can:
- `paradigm override <id>` — interactive escape hatch
- `PARADIGM_OVERRIDE=<id> <cmd>` — one-shot scripted escape
- Resolve the underlying issue and re-run

Override events are written to `.paradigm/events/overrides.jsonl` for Loid's
calibration pass — if you generate too many overrides, Loid will surface
your block as noise. Self-regulate.
```
