**NEGCTRL-RIPPLE pre-declaration.** Sandbox construction work surfaced an engine
property: essence inlines local callee **bodies**, so a callee body-only edit
ripples into its caller's essence — callee-const × caller-const dual edits KNOT
even though both intents commute (truth=mergeable). An honest catalog must not
dodge a known over-block, so 3 such seeds are included and **expected to score
FALSE-KNOT**. They spend the K2 guardrail budget deliberately: planned expectation
3 false-KNOTs ≤ ~32 expected meaning-decisive.

**K3 churn model pre-registration (construct-validity declaration, made BEFORE the
run).** Overturns are generated by 20 churn slots (sessions 3–12, unscored FAST
positions): each retires one module chosen **uniformly at random (fixed PRNG) over
modules admitted ≥2 batches earlier — never conditioned on prior class**. Under
this prior-blind null model the *expected* linked-vs-independent survival gap is
≈ 0 by construction: every sealed CLEAN in this catalog is authored-mergeable, so
no overturn can be *caused* by a bad independent merge. The alternative — churn
conditioned on prior class — would author K3's answer, which is worse than
measuring it. **Declared consequence: K3 as pre-registered is expected to fire on
this seeded arm regardless of engine quality.** We run it anyway, report the exact
numbers, and treat a K3 firing as a *construct finding about the seeded arm*
(organic-arm evidence is the fair K3 test), while still reporting it as the
pre-registered gate demands. The K3 verdict line below states both.

**Adjudication oracles** (Column C): authored ground truth (primary, §2.3.4) +
`tsc --noEmit --strict` on both candidate result trees (external corroborator) +
git merge-tree counterfactual (Column A). The spec's "targeted test subset" oracle
is not run: for this synthetic seed language (arithmetic one-liners) a test oracle
is derivable from the same authored truth and adds no independent signal; tsc is
the type-level external check. Disclosed as a limitation.

**Tree**: throwaway monorepo clone — `git archive` of live HEAD `0d317aa3` with

run: the throwaway fabric is born post-TD-721 (schema-v2 strands only, no v1

**Seeded-construct honesty (spec §1.4/§6):** every row in this run is seeded; there

## §5. The FALSE-CLEAN hard stop — root cause and disposition

**Raw finding:** 8 FALSE-CLEANs. **Every one is the same shape**: a *single-sided*
INDEPENDENT row applying **side A of a TRUE-INTERFERENCE-ripple seed** (f107, f123,
f140, f156, f163, f164, f187, f192 — 8/8, no exceptions).

**Root cause (verified, not asserted):** TI-ripple's `patchA` is the construction's
callee-contract change (callee gains a required param) with the caller deliberately
untouched — that untouched caller is what makes the *merged* tree broken in the pair
event. Consequence: **`patchA` alone does not typecheck.** Verified independently:
`tsc --strict` on each of the 8 seeds' standalone `patchA` files fails with the same
`TS2554: Expected 2 arguments, but got 1` BEFORE any merge exists. On these rows
`tscGit` fails identically (both result trees inherit the same broken input) — the
failure is carried by the input, not created by the composition. Warpline sealed a
CLEAN merge of an already-broken proposal; warpline is not a typechecker and the
wrong-merge definition (§2.3: the MERGE introduces the breakage) does not hold here.

**Disposition:** per harness-spec §1.1's own falsifiable-catalog rule ("a pair whose
authored truth disagrees with its tsc adjudication is quarantined and flagged"),
these 8 ROWS are quarantined as mis-scheduled seed usage (the pilot never scored a
TI side-A single-sided; this run's slot design did — a harness bug, not an engine
bug). Metrics both ways: raw 32/144 = 22.2% vs quarantined 32/136 = 23.5%; K1/K2
verdicts identical under both. **Engine wrong-merge count: 0.**

**Taint disclosure (applies to the 12 silent-mismerge catches too):** the same
standalone-brokenness of side A means the pair rows' tsc corroboration is weakened —
the merged tree's TS2554 would fire even absent side B's edit. The catch label
stands on (a) authored truth = conflict (the primary adjudicator for seeded rows,
§2.3.4 — the interference is real: A changed the contract, B extended the caller
assuming the old contract) and (b) the operational difference that git lands the
broken tree silently while warpline blocks it. A type-level ripple construction
whose side A is standalone-well-formed appears impossible (updating the caller in A
destroys the git-clean-merge property); a future iteration should corroborate with
behavioral tests instead of tsc. Disclosed per the ground rule that a workaround
biasing a stratum must be surfaced.

**Harness fix filed (§7):** adjudicator gains an input-health precondition column
(tsc each proposal standalone; a row whose input fails is scored against a
degraded-input baseline instead of FALSE-CLEAN), and the manifest generator must
never schedule a not-standalone-well-formed side as a scored single-sided row.

## §7. Findings surfaced (dogfood value)

1. **ENGINE — essence inlines callee bodies; commuting dual edits over-block
   (FALSE-KNOT cost, now measured).** A callee body-only const tweak ripples into
   the caller's essence (`sem-delta.ts` code-unit contentId incl. inline-substituted
   local refs), so callee-const × caller-const edits KNOT although both intents
   compose. Measured: 3/3 NEGCTRL-RIPPLE rows FALSE-KNOT (100% of graph-coupled
   commuting dual edits in this catalog). This is the wedge's over-block price:
   every such KNOT is an unnecessary human interrupt. Candidate refinement: contend
   on ripple only when the callee's *contract* (signature slots) changed, not on
   body-ripple alone — needs its own falsifier before adoption.
2. **ENGINE (positive) — the AUTO-RESOLVE wedge is real at 100% on this catalog.**
   20/20 git-textual-conflicts whose meaning commutes sealed CLEAN via token-level
   merge3 (`materialize.ts`/`merge3.ts`), every merged tree typechecks, both
   linked and independent flavors, including merges landing on merge strands (H1
   relaxed native path). H1-wall 0/124.
3. **HARNESS BUG — TI-ripple side-A is not standalone-well-formed** → 8 spurious
   FALSE-CLEANs when scheduled as scored single-sided rows (§5). Fix: input-health
   precondition in `adjudicate.mjs` + scheduling constraint in
   `gen-manifest-full.mjs`.
4. **HARNESS-SPEC FINDING — K3 is structurally untestable on a fully-seeded arm.**
   Any prior-blind churn yields gap ≈ 0 by construction; prior-conditioned churn
   would author the answer. The only honest seeded alternative (hidden-conflict
   seeds that later manifest) weaponizes the FALSE-CLEAN hard stop against its own
   run — a spec contradiction. K3 must be re-scoped to the organic arm.
5. **PERF — monorepo-scale write path held up.** 192 admissions on a 2,583-file
   tree: median admit 5.6s, p90 8.7s, max 14.4s (cold genesis pick 5.1s); no
   runaway growth across 48 batches (first-3 batch mean 4.3-5.2s ≈ last-3
   4.2-5.1s). Confirms T-2026-07-04-003 at ~40× the pilot's admission count.
   Oracle (~8.5s/call) is now the dominant per-row cost.
6. **Driver quirk:** the first multi-session driver invocation was killed at a
   10-minute exec cap; orphaned children kept running and completed session-safe
   (per-session invocations + append-only JSONL made the run resumable/auditable).
   Crash-resume flags (`--from-batch`, `--resume-partial`, `--max-batches`) were
   added to `swarm.mjs` but ended up unused.
