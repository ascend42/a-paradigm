## Journey 1: New User Installing for Claude Code

### Task Attempted
Install graphify, connect it to Claude Code, and successfully run `/graphify .` on a local project folder.

### Step-by-Step Walkthrough

**Step 1:** Read the headline and opening paragraph.
- Outcome: Success — clear entry point, "Type `/graphify` in Claude Code" is direct.
- Friction: none

**Step 2:** Read the "How it works" section.
- Outcome: Confused
- Friction: `undefined_term` — medium
- Note: "Leiden community detection," "NetworkX graph," "INFERRED vs EXTRACTED vs AMBIGUOUS" — none defined before use. Erodes confidence this tool is for them.

**Step 3:** Read the Install section prerequisites.
- Outcome: Partial success
- Friction: `assumed_context` — medium
- Note: Python 3.10+ is stated as a requirement, but no "how to check your version" guidance. macOS users often have Python 3.9 from Homebrew and won't know to check.

**Step 4:** Run `pip install graphifyy && graphify install`.
- Outcome: Confused then recovered
- Friction: `contradictory` — high
- Note: Package is `graphifyy` (two y's) but CLI/skill is `graphify` (one y). The blockquote explanation is present but reactive — a skimming user misses it, searches PyPI for "graphify," finds nothing useful, files a bug.

**Step 5:** Check the Platform support table.
- Outcome: Success
- Friction: none

**Step 6:** Open Claude Code, type `/graphify .`.
- Outcome: Blocked
- Friction: `missing_coverage` — critical
- Note: No step explains what `graphify install` actually does — what file it places, where, or how Claude Code discovers it. The Manual Install section (collapsed `<details>` block) reveals destination is `~/.claude/skills/graphify/SKILL.md` and `~/.claude/CLAUDE.md` must be updated — but this is buried and opt-in to read. No confirmation mechanism exists for the auto-install path.

**Step 7:** Attempt to troubleshoot if `/graphify` doesn't respond.
- Outcome: Blocked
- Friction: `missing_coverage` — critical
- Note: No troubleshooting section, no FAQ, no "if it doesn't work" path anywhere in the README.

**Step 8:** Read "Make your assistant always use the graph."
- Outcome: Confused
- Friction: `assumed_context` — medium
- Note: "After building a graph, run this once in your project" — but this section appears before Usage. A top-to-bottom reader will run `graphify claude install` before they have a `graphify-out/` folder.

**Step 9:** Note the PreToolUse hook mention.
- Outcome: Confused
- Friction: `undefined_term` — low
- Note: "installs a PreToolUse hook (settings.json)" — which `settings.json`? Project-local or global? Never specified. No path to inspect or understand what changed.

## Journey 2: New User Installing for Codex

### Task Attempted
Install graphify for Codex, configure it correctly, and run the equivalent of `/graphify .` on Codex.

### Step-by-Step Walkthrough

**Step 1:** Run `pip install graphifyy && graphify install`.
- Outcome: Partial — see Journey 1 Step 4 for the double-y confusion.

**Step 2:** Read Platform support table — see Codex requires `graphify install --platform codex`.
- Outcome: Confused
- Friction: `contradictory` — high
- Note: Top-level install command omits the `--platform codex` flag. The table below shows Codex needs it. No callout bridges them. A Codex user who ran the top command has installed the wrong platform with no error.

**Step 3:** Read the `multi_agent = true` requirement.
- Outcome: Blocked
- Friction: `missing_coverage` — critical
- Note: "for parallel extraction" makes this sound optional/performance-related. Does the skill work at all without it? Does `~/.codex/config.toml` exist by default? What does the full config block look like? Zero guidance provided.

**Step 4:** Open Codex, try to run the skill.
- Outcome: Blocked
- Friction: `buried_info` — critical
- Note: The `$graphify .` vs `/graphify .` distinction for Codex is in a small Note callout inside the platform section — nowhere near the headline "Type `/graphify` in Claude Code, Codex..." that a reader takes at face value. A Codex user types `/graphify .`, gets nothing, has no obvious next step.

**Step 5:** Run `graphify codex install`.
- Outcome: Confused
- Friction: `assumed_context` — medium
- Note: Writes to "AGENTS.md in your project root." No explanation of what AGENTS.md is, whether it's a Codex convention, or how Codex reads it.

**Step 6:** Attempt to verify install worked.
- Outcome: Blocked
- Friction: `missing_coverage` — critical
- Note: Same gap as Journey 1 Step 6 — no verification step, no expected output, no confirmation mechanism on any platform.

## Journey 3: Power User — Advanced Features

### Task Attempted
Use `--update`, `--watch`, `graphify claude install`, and `graphify query` as described in the Usage section.

### Step-by-Step Walkthrough

**Step 1:** Run `/graphify ./raw --update`.
- Outcome: Confused
- Friction: `missing_coverage` — medium
- Note: What happens when `--update` is run with no existing graph? Creates one? Errors? Not stated.

**Step 2:** Run `/graphify ./raw --watch`.
- Outcome: Partial success
- Friction: `assumed_context` — medium
- Note: "run in a background terminal" — how to background it on Windows vs macOS vs Linux is unspecified. "Doc/image changes notify you" — notify how? Terminal output? Desktop notification? Mechanism unspecified.

**Step 3:** Run `graphify claude install`.
- Outcome: Confused
- Friction: `assumed_context` — high
- Note: CLAUDE.md: append vs overwrite? Safe if existing project CLAUDE.md has content? Which settings.json — global or project-local? Does the PreToolUse hook affect performance on large repos (fires before every Glob and Grep)? None answered.

**Step 4:** Run `graphify claude uninstall`.
- Outcome: Confused
- Friction: `missing_coverage` — medium
- Note: No detail on what is removed or how to verify clean state after uninstall.

**Step 5:** Run `graphify query "..."`.
- Outcome: Confused operationally
- Friction: `missing_coverage` — medium
- Note: Default `graph.json` path never stated. A user running from a different working directory than where they built the graph will hit an error with no guidance on how to specify the path (the `--graph` flag is documented, but the default is not).

**Step 6:** Try `--dfs` flag.
- Outcome: Confused
- Friction: `undefined_term` — medium
- Note: `--dfs` described as "trace a specific path" — DFS (depth-first search) is a technical term not all developers know. No plain-English description of what it produces differently vs default BFS.

**Step 7:** Try `--budget 1500` flag.
- Outcome: Success
- Friction: `undefined_term` — low
- Note: "cap at N tokens" — input, output, or total? Relevant to API cost management.

**Step 8:** Run `graphify hook install`.
- Outcome: Confused
- Friction: `assumed_context` — high
- Note: No explanation of: which `.git/` gets the hooks, how it interacts with existing hooks or hook managers (husky, lefthook). Critical undisclosed behavior: "If a rebuild fails, the hook exits with a non-zero code" — a failed graph rebuild **blocks a git commit**. This is not flagged as a warning, just stated as a feature.

**Step 9:** Try `graphify add <url>`.
- Outcome: Confused
- Friction: `missing_coverage` — high
- Note: No narrative context anywhere in the README. Does it require an existing graph? Where are fetched files saved? What is the distinction between `--author` (who wrote it) and `--contributor` (who added it) and does it affect the graph structure?

## Verdict

**Overall readiness: needs-work**

Three issues stand out as likely blockers for new users: (1) no confirmation or verification path after install on any platform, leaving users unable to tell if setup succeeded; (2) the Codex `$graphify .` vs `/graphify .` distinction is buried far from where users are told to type the command, guaranteeing silent failure for linear readers; (3) the `multi_agent = true` Codex requirement lacks an example config and explanation of consequences, leaving Codex users at a dead stop with no next step.
