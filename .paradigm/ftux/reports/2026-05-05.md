## Step-by-Step Walkthrough

### Step 1 — Landing on the README

A new user reads the README. The headline is "One command to make your codebase AI-ready." The "Run it" section immediately shows `paradigm shift`, not `paradigm init`. This is correct — README was updated in v6.2.1 (CHANGELOG confirms F-03 doc drift fix).

However, the user then scrolls to the `paradigm shift` section. On first read, the "What you just got" section shows a `.purpose` skeleton they should fill in, and separately shows a `portal.yaml` skeleton. Neither section explains *when* to fill these in relative to the setup flow. The README shows the skeletons in the middle of explaining what shift does — which reads as "here's what to eventually fill in" — but there is no explicit instruction saying "do this now" vs "do this later."

The "Useful commands" table at the bottom lists `paradigm init` without explanation of how it relates to `paradigm shift`. A new user who sees both listed with no relationship explanation may attempt `paradigm init` first.

### Step 2 — Installation

README install instructions are clear: `npm install -g @a-company/paradigm`. The install script one-liner is buried in a collapsed `<details>` section, which is fine.

The quick-start guide repeats the same install instructions. No duplication problem — this is expected for a guide.

However, the quick-start guide's "Super Quick Setup" block is:

```
paradigm shift && paradigm mcp setup --client all && paradigm constellation && paradigm beacon
```

This is presented BEFORE the step-by-step breakdown, and `paradigm constellation` is not mentioned in the "Key Commands Reference" table directly below it. A user who runs the super-quick line sees `constellation` in the output, then can't find it in the table to understand what it did.

### Step 3 — Running `paradigm init` vs `paradigm shift`

The `docs/commands/init.md` command reference is stale. It says:
- "Don't run multiple times" and "Use `paradigm upgrade` to update"
- Its "Initial Setup" example uses `paradigm init --quick` not `paradigm shift`
- Its troubleshooting says "Use `--force` or `paradigm upgrade`"
- The integration workflow example reads: `paradigm init --quick` → `paradigm beacon` → `paradigm constellation` → `paradigm mcp setup`

The CHANGELOG (v6.2.1, F-03 fix) says quick-start.md and mcp-setup.md were updated from `paradigm init --quick` to `paradigm shift`. But `docs/commands/init.md` was not updated. A user who clicks "See Also → Quick Start Guide" from `init.md` will get the updated guide — but users who land on `init.md` directly from searching see a contradictory flow.

The `paradigm --help` output lists both `init` and `shift` at the top level with no indication that `shift` supersedes `init` for new users. `init` is listed first. A user who runs `paradigm --help` will likely run `init`.

### Step 4 — Following the quick-start guide

The guide's step-by-step section has a subtle inconsistency. Step 2 says:

```
# 2. Initialize Paradigm (non-interactive, uses auto-detected defaults)
paradigm shift --quick
```

But step 3 says:

```
# 3. Generate IDE instruction files
paradigm sync --all
```

The README says `paradigm shift` runs all IDE syncs as part of its flow (step 4 of what it does: "Generates IDE instruction files"). So step 3 in the guide is redundant after `paradigm shift`, but the guide doesn't say this. A user running the step-by-step path runs the sync twice without knowing it.

The guide also does not mention the `none` enforcement default (new in v6.3.0). After running `paradigm shift`, the user sees "Enforcement: none — symbol tracking available when you're ready. Rune will guide you." in the output (per CHANGELOG). But the quick-start guide has no explanation of what this means or what to do next. The user sees Rune mentioned but the guide never introduces Rune.

### Step 5 — First command after setup

The README "What your AI sees" section says to call `paradigm_related` or `paradigm_ripple` after setup. But the quick-start guide's "Next Steps" section says:

1. Add features — Create `.purpose` files
2. Define gates — Create `portal.yaml`
3. Use the logger — Follow patterns in `.paradigm/specs/logger.md`
4. Get AI help — Use prompts in `.paradigm/prompts/`

Item 3 points to `.paradigm/specs/logger.md` — a file that only exists after `paradigm shift` and is not user-facing documentation. The quick-start guide points the user to an internal spec file as a "next step." A new user who clicks this link will not find it in the docs — they'd have to navigate into their project's `.paradigm/` directory.

Item 4 points to `.paradigm/prompts/` — same issue. This is a project-local directory, not a doc link.

### Step 6 — Claude Code plugin path specifically

The plugin README says to run `/paradigm:shift` as the first step in "Getting Started" for new projects. The main README says to run `paradigm shift` (CLI). These are two separate invocation patterns. The plugin README does not explain that `/paradigm:shift` is a Claude Code skill that wraps the CLI `paradigm shift` — it just says to use it. A Claude Code user who installed the plugin first (before installing the CLI) could be confused when `/paradigm:shift` triggers a bash call to `paradigm shift` and they see CLI output they didn't expect.

The plugin README's "Requirements" section lists `@a-company/paradigm npm package (auto-installed via npx)`. But `paradigm shift` in the hook scripts may fail if the global CLI is not installed — the "auto-installed via npx" claim only applies to the MCP server, not the CLI. This is a subtle but potentially confusing distinction.

## Verdict

The core happy path (README → install CLI → `paradigm shift` → `paradigm mcp setup`) is functional and well-documented. The two major gaps are:

1. **`docs/commands/init.md` was not updated when quick-start.md was fixed in v6.2.1.** It still teaches the old `paradigm init --quick` flow. This is the highest-severity finding because it directly contradicts the current recommended path for any user who finds init.md via search or the `--help` output.

2. **The v6.3.0 enforcement-default change (`none`) is not surfaced in the quick-start guide.** A new user running `paradigm shift` will see the awareness line in terminal output but have no guide context for what it means, who Rune is, or how to act on it.

The remaining findings are medium/low: init vs shift command ambiguity in `--help`, `paradigm constellation` missing from the key commands table, redundant sync step in the quick-start walkthrough, and "next steps" links pointing to project-local files rather than documentation.
