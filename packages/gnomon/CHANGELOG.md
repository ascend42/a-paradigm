# Changelog — @a-company/gnomon

Gnomon changes on `feat/gnomon` before they reach a Paradigm release. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **The Desk O1 integration** (TD-2026-10-20-812, `#gui-offer-slip`). The GUI margin slip now uses the real contracts: offer kinds, id, mod and token patterns, `CONTEXT_SOURCES` (recent-messages, open-files, repo-path, selection, session-summary), and the `isOfferTitle` and `isOfferQuestion` text rules. A reply's trailing ```offer block is hidden (contracts `offerBlockOf(text).body`) only when a valid kernel `offer.shown` row anchors to that reply and names the same mod and kind. Without that row the reply shows as-is, so model text alone never hides anything. The served GUI bundle has been regenerated and its hash repinned.
- **The Desk's kernel core** (TD-2026-10-20-812, slice S1, `#desk-guidance`, `#offer-router`, `#mcp-passthrough`, `$offer-handoff`, `^offer-accept`). While a session has an installed, granted mod that declares offers, every turn carries a frozen `<gnomon-desk>` note and a roster built from manifest fields only. The note shares the turn's single guidance block with table talk, under one `guidanceHash` that `gnomon trace` accepts. At a turn end the kernel parses the reply's one ```` ```offer ```` block and writes `offer.shown`, with phase, title and `contextIn` copied from the manifest. It shows at most one offer per reply, none mid-stream and none while a card is pending, and only for an installed, unmuted mod's declared offer. `request.offer.decide` and `request.offer.mute` are served only for the human on a GUI or device connection. A decision needs a live offer, the latest in its session, and takes exactly one decision. On open the kernel sends a templated turn as the human. `offer.kept` is written when the mod's declared handoff tool then succeeds. Granted mods' MCP servers join the session `mcp.json` as `gnomon-<mod>`; a repo server is never shadowed and repo-muted mods are skipped. A server whose resolved command is not an absolute path (both shipped first-party defaults, until configured) is left out and reported as needing `gnomon mod config` (fail closed). New CLI: `gnomon mod config <mod> --command <abs> --args …` requests a per-user launch override. It is kept in kernel state only and decided on a card that shows the command, args, env names and launch hash. `gnomon desk stats` shows kept/shown per mod. Aegis S1 fixes: repo MCP servers named with a reserved desk prefix (`gnomon-`, `gm_`, `gx_`) are dropped; offers and kept count only through servers actually added to that session; the open turn names the fully qualified tool; offer titles refuse `<` `>` `"` and backticks (contracts, shared with the GUI); secret-marked env names cannot be set by override; the launch hash is an HMAC under a kernel key; on Windows an override command must be an `.exe`; the next turn retires a shown offer; pause and mute apply to running sessions' offers at once and to their MCP servers from the next session. Spec §12.9; Appendix A 63 → 68 nodes (`G-DSK-01..05`).
- **The Desk's wire shapes, reserved in one `clientApiId` move** (TD-2026-10-20-812, slice S0, `#gnomon-contracts`, `#manifest-loader`). Contracts only, so no later Desk or context-meter slice moves the id again. New kinds `offer.shown`, `offer.decided`, `offer.kept`, `request.offer.decide`, `request.offer.mute`, `request.mod.install`, `request.session.restart` and `session.context.threshold`, each with a closed payload; `offer-spec:v1` with the closed `CONTEXT_SOURCES`; `offerBlockOf`, the one strict parser of a model's ```` ```offer ```` block, shared by the kernel and the GUI. Manifests gain `provides.offers` (at most 6, a widening field), a closed per-user override for a `provides.mcp` server's command, args and env, and the reserved mod names `kernel`, `gnomon` and `system`. Install cards show one line per offer. `clientApiId` `sha256:69e8db86…cc0e` → `sha256:40efb7259e10d288f08c951ea22af72c76d149a6bd38c395ae7df3dfa8942afd`. The embedded GUI bundle is re-embedded because it bundles the contracts (`GUI_BUNDLE_HASH` moved).
- **Aegis fixes to S0** (no `clientApiId` move). An mcp override's env names are checked against a wider denylist of exact names and prefix families. Below the first-party tier a declared env name must start with the mod's own prefix or end in `_API_KEY` / `_TOKEN`, and a user-set command must be an absolute path. Each `contextIn` source is now its own widening key, and the offer card line says `takes:`. Install paths refuse UNC and device prefixes, `:` after the drive, and segments made only of dots and spaces. An ```` ```offer ```` block must end the reply. The parser refuses a bare CR, allows other fences to be indented up to 3 spaces, and refuses lone surrogates, private-use characters and more than 3 combining marks in a row. More mod names are reserved, and the first-party names (`workshop`, `ledger`, `paradigm-context`, `neurons`, `constellation`) and the prefixes `gnomon-`, `paradigm-`, `claude-` and `anthropic-` are accepted only from the first-party tier.

### Changed

- **A start without a terminal opens the GUI** (T-2026-10-20-001, `#gui-relaunch`). `gnomon up` and bare `gnomon` with no interactive terminal, and `gnomon daemon start | --detach` / `gnomond` (activator) after a fresh start, open a new GUI window in the default browser. The single-use launch URL goes only to osascript's stdin and is never printed. **Opt out:** `--no-open` or `GNOMON_NO_OPEN=1`. `gnomond --foreground --no-open` is a usage refusal.
- **A stale GUI tab no longer points to a terminal as the only way back.** It says Gnomon stopped, treats an answer at its old address as unverified (it never suggests a reload), and offers "Close this tab" only when a same-origin window signals it attached.

### Security

- No web port is remembered across a restart (Aegis H1). Each plain start binds an OS-chosen port, and any `web-port.json` left over from the withdrawn build is deleted without being read.
