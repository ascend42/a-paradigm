Gnomon changes on `feat/gnomon` before they reach a Paradigm release. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

### Added

- **auto-edits passes more read-only command families** (founder decision 2026-10-20, `#shell-readonly`, `#supervisor`, spec §3.4 "Read-only widening"). In the dogfood, auto-edits raised Bash cards for a `grep -rn … | grep -v … | head; which gnomon`, for `gnomon desk stats 2>&1 | head -80` and for `paradigm status 2>&1 | head -60`; native Claude Code would not have asked for the grep. The bar is never to prompt more than native in the same mode. In an anchored posix run (win32 and unanchored callers are unchanged) the classifier now also passes `grep -r`/`--recursive` (not `-R`/`-S`/`-O`/`-d`/`-D`), `rg` (not `-L`, `-z`, `--pre`, `--pre-glob`, `--hostname-bin`), `fd` (not `-x`, `-X`, `-l`, `-L`), `tree` (not `-o`, `-R`, `-l`, `--fromfile`), `git remote -v`, and exact read-verb grammars for `paradigm` (`status`, `doctor`, `ripple`, `purpose validate`, `task ls`, `task show`) and `gnomon` (`desk stats`, `daemon status`, `mod list`, `mod status`, `rules list`, `trace status`, `replay`). Each verb was checked read-only in its source; `paradigm lore list/show` (legacy migration moves files) and `paradigm index` (writes) are left out, and a paradigm command is a card while `.paradigm/` lacks the marker its preAction notice would write. The anchor prelude also unsets `RIPGREP_CONFIG_PATH`. Every earlier rule still applies to the new families: every segment of a compound must pass, output redirection only to `/dev/null`, no env prefix, `eval`, `exec`, `xargs`, `tee` or `sed -i`, no substitution as a path, reads only inside the session and system read roots. New test file `test/shell-readonly-widen.test.ts` (183 cases); the pure table now expects the unanchored refusals. ### Fixed

- **Paradigm read verbs pass on their grammar alone** (`#shell-readonly`, spec §3.4 RW). The classifier no longer turns `paradigm status`, `doctor`, `ripple`, `purpose validate` and `task ls/show` into a card while `.paradigm/` lacks the v6.0.4 notice marker or the roster lacks `compliance`: from `@a-company/paradigm` 7.15.2 those verbs write nothing (the notice prints to stderr only, `#command-policy`), proven by paradigm's `readonly-commands.test.ts`. `paradigm lore list|ls [filters]` and `paradigm lore show L-ID` join the allow set, since lore reads no longer migrate legacy entries. `task show REF` now refuses a path separator and `lore show` takes only an `L-[A-Za-z0-9_-]+` id: the CLI joins a dated id into a file path.
- **The paradigm read verbs check the paradigm version** (`#shell-readonly`, `#auto-edits`, `#supervisor`). They pass only when the first `paradigm` on the session env's `PATH` resolves (realpath, then the nearest `package.json`, read once per path and mtime) to `@a-company/paradigm` 7.15.2 or newer. An older CLI, a prerelease of 7.15.2, another package, a shim, an unknown PATH or a relative PATH entry is a card. `BashAnchor.path` carries the session PATH into the classifier (`ReadOnlyContext.searchPath`).
- **G-GUI-12 deflaked** (re-review L-5, T-2026-10-21-008, `test/wrapper-channel.test.ts`). The real-process falsifier captures the child's exit promise at spawn, records non-JSON stdout lines instead of throwing in the data handler (and asserts there are none), waits up to 45 s for `up`, and has a 90 s budget. A sequential/singleFork vitest project is deferred: the config has one project, and splitting it would touch the platform-registry include/exclude.
- **A repainted kept item is measured again** (re-review L-4, T-2026-10-21-008, `#gui`). The H1 repaint remounted a stale kept item but kept its old measured height; `HeightIndex.invalidate(i)` now resets each remounted stale index to the estimate until it is measured.
- **A network-failed send says it may not have been sent** (re-review L-3, T-2026-10-21-008, `#gui`). The kernel may have received a send whose answer was lost, so the line reads "may not have been sent: the connection to the kernel failed".
- **Replay lines before the stream is live are ignored** (re-review L-2, T-2026-10-21-008, `#offer-router`, `#supervisor`). A replay before the first `system.init` or `turn.sent` (a resumed session's history) no longer switches the router to started marks or counts as a consumed turn.
- **The offer budget and turn attribution in two edge cases** (re-review L-1, T-2026-10-21-008, `#offer-router`). With replay lines, a queued turn Claude Code has not consumed no longer suppresses the running reply as `turn-streaming`. Without replay lines, a continuation that arrives after every outstanding turn was evaluated stays in the previous message's turn instead of re-opening the oldest one.
- **The Stop-hook block match is exact** (re-review M-4, T-2026-10-21-008, `#offer-router`). `/block/i` on `outcome` matched `non-blocking`; the router now matches `outcome === 'blocked' || decision === 'block' || exit_code === 2`. Probe `p-replay-order` shows `hook_response` lines appear only under `--include-hook-events` (a block is `exit_code` 2, `outcome` `error`), which the adapter does not pass, so the branch is labelled speculative; a block today arrives as the hook's feedback line plus a new `message_start`, which the continuation path already handles.
- **`gnomon desk stats` no longer double-counts a continuation** (re-review M-3, T-2026-10-21-008, `#offer-router`). An offer retired before any decision is subtracted from shown and reported as retired (`shown N (+R retired)`, `--json` `retired`). A suppression counts once per (hsid, session epoch, turn), the epoch being the seq of the hsid's latest `session.open`, so a re-evaluated turn counts once and a resumed session's `/1` still counts.
- **A continuation retires an offer on the signed log** (re-review M-2, T-2026-10-21-008, `#offer-router`, `#gui-offer-slip`, `G-DSK-03`). A Stop-hook continuation retired the shown offer only in the router's memory, so a restart made it decidable again and the GUI slip stayed open. The router now returns the kernel row `offer.retired{offerId, hsid, why:'continued'}` for an undecided offer (a decided one, or one being decided, stays), folds it (also in `seed()`), and refuses a decide on it with reason `retired` ("this offer was withdrawn: Claude continued the reply it was shown for"). The GUI closes the slip and shows "retired · the reply continued · mod:<name>".
- **Turn pairing is backed by a probe, and a stray result is recorded** (re-review M-1, T-2026-10-21-008, `#supervisor`, `#offer-router`, `#gui`, `#gnomon-probes`). New probe `p-replay-order` runs the real pinned claude (2.1.305) with the adapter's stream flags. Claude Code writes a queued message's replay line when it consumes the message, never on receipt: B sent during A's Bash call is echoed after A's `tool_result` and one result (`num_turns` 2) closes both; B sent after A's final `message_stop`, back to back, or inside a Stop-hook continuation is echoed after A's result with its own result. So the fold rule stands, now cited in the code and spec. A result with no outstanding turn writes `session.anomaly{hsid, why:'result-without-turn'}`.
- **`offer.retired` and `session.anomaly`, one deliberate `clientApiId` move** (T-2026-10-21-008, re-review M-1/M-2, `#gnomon-contracts`, `#kernel-log`, reservation tag `8.0:T-2026-10-21-008`). Two kernel-owned, `normal` kinds with closed payloads, checked at append: `offer.retired{offerId, hsid, why:'continued'}` (descriptor `desk.retire`) and `session.anomaly{hsid, why:'result-without-turn'}` (descriptor `sessionAnomaly`). `clientApiId` `sha256:4c2b9371…af2c` → `sha256:454cd632007a77540a4526bebb55384d40e7935ad677e5dd9bf185595c77e4de`; the event schema, the ids pin and `gnomon-client-api.md` are regenerated and the pins updated.
- **The working row is announced once, not every second** (review a11y, `#gui`). It is now `role="status"` with the label "Claude is working", and its ticking clock span is `aria-live="off"`.
- **`gnomon desk stats` counts only the kernel's offer rows** (review C2, `#offer-router`). The fold counted any `offer.shown` / `offer.suppressed` row in the verified log; it now counts only rows whose envelope principal is the kernel principal.
- **`offer.suppressed` names a turn of its own session** (review C1, `#gnomon-contracts`, no `clientApiId` move). The closed check now refuses a `turn` whose id does not embed the payload's `hsid`.
- **A Stop-hook continuation no longer leaves the wrong message's offer** (review R2, `#offer-router`, `G-DSK-02`). The router evaluated at the first `end_turn`, so when a Stop hook blocked and Claude continued in the same turn, the offer belonged to a message that was no longer the reply. The evaluation now runs at `message_stop`; a new main-chain message in that turn before its `turn.result` (or a blocking Stop `hook_response`) retires the shown offer and the continuation's own end is evaluated. Replay lines mark which turn the stream is in, so a queued turn folded into a later one settles without a row. Spec §12.9 updated.
- **An interleaved stream no longer loses the next turn's offer** (review R1, `#offer-router`). The router kept a single evaluated head id, so when turn 2's reply ended before turn 1's `turn.result`, turn 2 was never evaluated and turn 1's result cleared its text. Each outstanding turn is now evaluated at most once on its own record, a reply's end goes to the oldest outstanding turn not yet evaluated, only turns still streaming suppress as `turn-streaming`, and `turn.result` keeps the text of a newer turn's message.
- **An errored or interrupted turn is not evaluated for an offer** (review R4, `#offer-router`). The `turn.result` fallback evaluated whatever text the turn had streamed, even when the turn ended in an error or an interrupt, and wrote an `offer.shown` or a suppression row for it. It now writes nothing when `turn.result.isError` is set or `subtype` is not `success`.
- **The offer router drops its turn state at a session boundary** (review R3, `#offer-router`). Outstanding turns, the current message text and the evaluation mark survived `session.exited`, `session.open` and `session.drained`, so a resumed session (turn ids restart at `/1`) could inherit a dead turn and suppress its first offer as `turn-streaming`. They are now cleared at each boundary; mutes and stop-here still last until the state is evicted.
- **`turn.result` names the turn it closes, and a folded queued turn settles** (review M2, `#gnomon-contracts`, `#supervisor`, `#gui`, `#offer-router`; one deliberate `clientApiId` move `sha256:eda8c627…1114` → `sha256:4c2b93711b219bff751f985286ba489bbc7015ad94627e954253186d3eeeaf2c`). `turn.result` carried no turn id, so every reader paired results FIFO by inference. In the dogfood log (seq 4795–5146) Claude Code folded turn 4 into the running turn 3: two `turn.sent`, one result, and the GUI's working row would have ticked forever. The supervisor now keeps the outstanding turn ids beside its turn permits and counts the turns Claude Code consumed (their replay lines). One result closes every consumed turn, releases each of their permits, and writes `turn.result{turn}`, the latest closed. The descriptor gains `turnResult` (`TURN_RESULT_PAIRING`). The GUI and the offer router close every open turn up to the named one; a row without `turn` pairs FIFO. The local lane names its turn too.
- **A refused send no longer desyncs turn anchoring** (review M1, `#gui`). A refused message stayed the "running" message, so the next send waited behind it, paired with the wrong `turn.sent` and showed the wrong working clock. The composer echo is now stamped with the turn id `session.send` returns and pairs with `turn.sent{turn}` exactly; a refusal or a network error marks it unsent (no turn: it never waits) and shows the reason under it.
- **A kept transcript item that changed in place is repainted** (review H1, `#gui`). The tail-only repaint remounted only the items from the first changed key onward, so when a reply landed after tools the activity line kept its key, lost its live clock in the data, but kept the `.live` class and a frozen "running 2m 6s" span on screen. Both repaint branches now remount every kept item whose rendered signature (role, text, liveness, "took", said-aloud line, voice marks; a card's decided state is its text) changed (`core/live-turn.ts` `itemSig` / `changedBefore`).
- **An offer is no longer dropped when the next turn is sent before `turn.result`** (T-2026-10-21-006, `#offer-router`, `$offer-handoff`, `G-DSK-02`). Claude Code can emit `turn.result` about 30 s after the reply's `message_stop`. The router evaluated the ```` ```offer ```` block only at `turn.result`, so when the human had already sent the next turn it silently dropped the offer as "another turn is streaming". The block is now evaluated when the main-chain assistant message stops with `end_turn` (`message_delta`, or an assistant line carrying the stop reason; `parent_tool_use_id` null). Only the turn's final assistant message is parsed, each turn is evaluated once, and `turn.result` evaluates only a turn whose end was not seen. A `tool_use` stop does not evaluate and a sub-agent's message is ignored. A turn sent after the reply ended no longer suppresses it; a turn sent while the reply was still streaming still does. The other gates (pending card, offerable mod, declared kind) are unchanged. Every evaluation that shows nothing now writes a kernel `offer.suppressed{hsid, turn, why, name?, offerKind?}` row to the signed log, so "no slip" can be told apart from "the model chose none". `why` is one of `no-block`, `turn-streaming`, `pending-card`, `not-offerable`, `kind-undeclared` or `malformed`; `name` (the mod id) and `offerKind` are present exactly when the block named them. Names only, never message text; the payload is closed and checked at append. At most one row per completed main-chain turn, and `no-block` only while the session has an offerable mod, so a session with no Desk mod writes nothing. `gnomon desk stats` shows `shown N · suppressed M (reason n, …)` per mod and the unnamed `no-block` / `malformed` counts per session (`--json`: `mods[m].suppressed`, `suppressedBy`, `unnamed`). The GUI folds the new kind into nothing visible.
- **`offer.suppressed`, one deliberate `clientApiId` move** (T-2026-10-21-006, founder ruling, `#gnomon-contracts`, reservation tag `8.0:T-2026-10-21-006`). New kernel-owned, `normal` kind `offer.suppressed` with a closed payload (`OFFER_SUPPRESS_REASONS`, `OFFER_SUPPRESS_UNNAMED`), and the descriptor field `desk.suppress{reasons, unnamed}`. `clientApiId` `sha256:4d883058…ccd8` → `sha256:eda8c627b60d11408b7c21ee45db889eb068cf135e6a362e293a46880c561114`. The event schema and `docs/specs/gnomon-client-api.md` are regenerated. The served GUI bundle embeds the contracts, so it must be rebuilt and repinned with the kernel (until then the GUI shows a non-fatal clientApiId drift).
- **A turn's result shows under its own turn, and a running turn shows that it is running** (T-2026-10-21-007, `#gui`). In the dogfood, turn 2's result ("success · $0.2973 · 8 tokens") arrived 22 s after its reply and after the founder had sent turn 3, so it rendered under turn 3's message and turn 3 looked finished while `paradigm doctor` ran for about 2 minutes; the activity line stayed at "29s of work". turn.result carries no turn id, so the GUI pairs it with the oldest open turn.sent (the backend answers in send order) and places the running turn's output and result above any message still waiting. While a turn runs, a `working… · Ns` row with a small spinner sits under it and its activity line counts live (`running 2m 10s · Bash 1m 33s`, from the turn start and the tool_progress heartbeats). When the result lands both freeze at the real duration. One 1 s interval runs while the focused session has a running turn and is cleared when it ends; it rewrites only the clock text. The served GUI bundle is re-embedded and `GUI_BUNDLE_HASH` repinned.
- **Sessions on an upgraded or detached daemon are no longer refused `not_subscription_auth`** (`#session-runner`, `#supervisor`). The clean re-exec (upgrade successor, `gnomon daemon --detach`) keeps no `USER`, and Claude Code finds its keychain credentials by `$USER`, so every session there failed the auth preflight (`authMethod: none`). A session's identity names now come from the OS, never from the daemon's env, so they are the same however the daemon was launched: `USER` and `LOGNAME` from `os.userInfo().username`, `SHELL` from `os.userInfo().shell` (absolute only) and, on macOS, `TMPDIR` from `/usr/bin/getconf DARWIN_USER_TEMP_DIR` (run with an empty env, accepted only as an absolute directory owned by the uid and not group- or world-writable). A value the OS cannot give is left out, never copied from the env. The identity is resolved once at daemon start. Windows is unchanged (`USERPROFILE` stays allowlisted; `USERNAME` is not in the allowlist). The user home is `os.userInfo().homedir`, never `$HOME`. An incomplete OS identity logs one `session.sandbox{phase:identity, missing}` row at daemon start (names only), and a `not_subscription_auth` refusal with no `USER` names the cause. The `session` profile's screen-socket deny follows the session's `TMPDIR`, else the literal `/private/tmp`.
- **Session `PATH` is config-or-default, never the daemon's** (TD-2026-10-21-077, `#session-runner`, `#supervisor`, `#budget-fuse`). New root-signed config key `config.sessions.path`: 1-32 absolute directories, each at most 1024 characters, no NUL/CR/LF, no `:` on POSIX (`;` on Windows). Unset, the default is, on macOS, the running node's directory, `<OS home>/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin` (Linux: the same without `/opt/homebrew/bin`). It applies on every launch path, including `gnomon up` in-process, which used to hand the terminal PATH to sessions; an upgraded or detached daemon's sessions get `/opt/homebrew/bin` (node, npm, gh) back. An invalid `sessions` section falls back (logged `config.loaded{why:invalid}`) and the default applies. Windows keeps the allowlisted PATH. No CLI verb writes the root config yet.
- **A Gnomon session in a repo with a generated distro kept its MCP server again** (`#mcp-passthrough`). S0b named the generated distro server `gm_<publisher>_<name>` (e.g. `gm_gnomon_paradigm-distro`), and the Desk's reserved-prefix rule then dropped it from every session's `mcp.json`, so a Paradigm repo silently lost the Paradigm server. The verified generated `.gnomon/generated/.mcp.json` is kernel output and now passes through. Repo-authored reserved names are still dropped. An installed mod deriving the same name still wins it, and a distro server never counts for offers or kept.

### Changed

- **A start without a terminal opens the GUI** (T-2026-10-20-001, `#gui-relaunch`). `gnomon up` and bare `gnomon` with no interactive terminal, and `gnomon daemon start | --detach` / `gnomond` (activator) after a fresh start, open a new GUI window in the default browser. The single-use launch URL goes only to osascript's stdin and is never printed. **Opt out:** `--no-open` or `GNOMON_NO_OPEN=1`. `gnomond --foreground --no-open` is a usage refusal.
- **A stale GUI tab no longer points to a terminal as the only way back.** It says Gnomon stopped, treats an answer at its old address as unverified (it never suggests a reload), and offers "Close this tab" only when a same-origin window signals it attached.

### Security

- **Every user-writable directory on the session PATH is write-denied** (TD-2026-10-21-162, Aegis M, `#session-runner`, `#supervisor`, `#manifest-loader`). With `~/.local/bin` and the node directory ahead of `/usr/bin`, a session could plant an `ls` or `git` that a later session's auto-passed read-only command would run with no card. The `session` profile now denies writes (never reads or exec) to `~/.local/bin` (also a persistence path), the node directory (by realpath) when it is user-writable, a Homebrew prefix as a whole (`/opt/homebrew`; on `/usr/local` only `bin`, `sbin` and `Cellar`; found by realpath, never `HOMEBREW_PREFIX`), and any other user-writable PATH entry. A PATH entry that is the home or above it is dropped. Sessions can no longer `brew install` or `npm i -g` into those prefixes: Edit/Write is refused by Claude Code's permission rule and the shell gets `Operation not permitted`. The daemon's law-7 user-settings scan and claude source lookup use the OS home (`os.userInfo().homedir`), not `$HOME`.

- No web port is remembered across a restart (Aegis H1). Each plain start binds an OS-chosen port, and any `web-port.json` left over from the withdrawn build is deleted without being read.
