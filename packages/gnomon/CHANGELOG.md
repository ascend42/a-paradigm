# Changelog — @a-company/gnomon

Gnomon changes on `feat/gnomon` before they reach a Paradigm release. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **One presence per decision, root-class included** (TD-2026-10-20-514, Aegis approve-with-conditions, `#gnomon-helper`, `#identity`, `#approval-broker`, `#manifest-loader`, `G-ID-09`, `G-ID-10`). In the dogfood, one mod install cost four typed passwords. Helper 1.8.0 adds `decision.sign`: one fresh presence signs the decisionSig, the presence challenge, the `gnomon-root-decision:v2` row and every grant row. The helper's dialog line comes first and names what each row grants. The kernel prepares the rows before the prompt, checks them against the card's `detail.rootRows` (inside contentHash), verifies every signature and the helper line, and commits once under a cross-process lock, `grant.install` last. Grant rows carry the `cardId`, and a row whose batch anchor is missing grants nothing. On a helper below 1.8.0 the same prepare/commit runs with one prompt per signature. `gnomon-helper probe-decision <gen>` is the on-device check.
- **One presence per decision, the rest of the families** (TD-2026-10-20-514 follow-up, `G-ID-09`..`G-ID-12`).
  - Uninstall, voice enrol, and a client-supplied decisionSig (the root-only `decision.sign` form) now each cost ONE presence (they cost 2 to 4). A count test covers every decision family.
  - `voice.enrol` is root class and hand-only. Its row signs the consent's hash, and the consent text never enters the card or the log (it stays in `voice/consents/`).
  - The GUI shows a root-class Approve only beside a verified, fully rendered "This decision signs" list. It flags red a logged `rowsDigest` that is not the digest of the rows it showed.
  - `status.helper.batch` reports `available` or `unavailable (helper <1.8.0)`, and the GUI shows a notice on a helper below 1.8.0.
  - `gnomon replay` checks every v2 root decision against the card it logged.
  - Aegis F1: the grants lock is never broken while live. F4: an install that was written but not decided is finished rather than refused.
  - Aegis final review: rootDecisions now sit inside the card's hashed detail, and the GUI fails closed, showing only deny/reject/withdraw, on any root-capable card whose rows it cannot verify (M1). The CLI `voice enrol` and `voice forget` take the same locked, seq-checked write path (M2). A deny over an install whose rows are already written is refused (M3). The grants lock is taken by an atomic link of a temp file holding pid:nonce (L1). A card enrol's row is still `voiceEnrolRow:v1`; it carries `consentHash`, and the text is in `voice/consents/<hex>.txt`.
- **S0b: mod naming and versioning** (TD-2026-10-20-812, `#gnomon-contracts`, `#mod-id-contract`, `#manifest-loader`, `#mod-host`, `#mcp-passthrough`, `#workshop-mod`). GitHub owners bind by the github.com rule and other hosts by TOFU `grant.publisher` rows. Install cards carry a version class (first, update, downgrade, same-version-new-bytes, format-only). New refusal codes are `FORMAT`, `ENGINE`, `PUBLISHER` and `COLLISION`. A mod's MCP server name is checked against installed mods and the user's own MCP server names (new `user-mcp.ts`, which reads only names from `~/.claude.json` and `<repo>/.mcp.json`). `status.mods.publishers` gives each running mod's publisher display, and the GUI shows `name (pub @ host)` or `name (pub, unverified)`. `clientApiId` moves once inside `8.0:TD-2026-10-20-812` to `sha256:4d8830585b5f676ee43c6d5d4a2cff35282344a0019526b2e66358c50599ccd8`; `status.mods.publishers` is a status sub-field and does not move it.

### Fixed

- **A turn's result shows under its own turn, and a running turn shows that it is running** (T-2026-10-21-007, `#gui`). In the dogfood, turn 2's result ("success · $0.2973 · 8 tokens") arrived 22 s after its reply and after the founder had sent turn 3, so it rendered under turn 3's message and turn 3 looked finished while `paradigm doctor` ran for about 2 minutes; the activity line stayed at "29s of work". turn.result carries no turn id, so the GUI pairs it with the oldest open turn.sent (the backend answers in send order) and places the running turn's output and result above any message still waiting. While a turn runs, a `working… · Ns` row with a small spinner sits under it and its activity line counts live (`running 2m 10s · Bash 1m 33s`, from the turn start and the tool_progress heartbeats). When the result lands both freeze at the real duration. One 1 s interval runs while the focused session has a running turn and is cleared when it ends; it rewrites only the clock text. The served GUI bundle is re-embedded and `GUI_BUNDLE_HASH` repinned.
- **Sessions on an upgraded or detached daemon are no longer refused `not_subscription_auth`** (`#session-runner`, `#supervisor`). The clean re-exec (upgrade successor, `gnomon daemon --detach`) keeps no `USER`, and Claude Code finds its keychain credentials by `$USER`, so every session there failed the auth preflight (`authMethod: none`). A session's identity names now come from the OS, never from the daemon's env, so they are the same however the daemon was launched: `USER` and `LOGNAME` from `os.userInfo().username`, `SHELL` from `os.userInfo().shell` (absolute only) and, on macOS, `TMPDIR` from `/usr/bin/getconf DARWIN_USER_TEMP_DIR` (run with an empty env, accepted only as an absolute directory owned by the uid and not group- or world-writable). A value the OS cannot give is left out, never copied from the env. The identity is resolved once at daemon start. Windows is unchanged (`USERPROFILE` stays allowlisted; `USERNAME` is not in the allowlist). The user home is `os.userInfo().homedir`, never `$HOME`. An incomplete OS identity logs one `session.sandbox{phase:identity, missing}` row at daemon start (names only), and a `not_subscription_auth` refusal with no `USER` names the cause. The `session` profile's screen-socket deny follows the session's `TMPDIR`, else the literal `/private/tmp`.
- **Session `PATH` is config-or-default, never the daemon's** (TD-2026-10-21-077, `#session-runner`, `#supervisor`, `#budget-fuse`). New root-signed config key `config.sessions.path`: 1-32 absolute directories, each at most 1024 characters, no NUL/CR/LF, no `:` on POSIX (`;` on Windows). Unset, the default is, on macOS, the running node's directory, `<OS home>/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin` (Linux: the same without `/opt/homebrew/bin`). It applies on every launch path, including `gnomon up` in-process, which used to hand the terminal PATH to sessions; an upgraded or detached daemon's sessions get `/opt/homebrew/bin` (node, npm, gh) back. An invalid `sessions` section falls back (logged `config.loaded{why:invalid}`) and the default applies. Windows keeps the allowlisted PATH. No CLI verb writes the root config yet.
- **A Gnomon session in a repo with a generated distro kept its MCP server again** (`#mcp-passthrough`). S0b named the generated distro server `gm_<publisher>_<name>` (e.g. `gm_gnomon_paradigm-distro`), and the Desk's reserved-prefix rule then dropped it from every session's `mcp.json`, so a Paradigm repo silently lost the Paradigm server. The verified generated `.gnomon/generated/.mcp.json` is kernel output and now passes through. Repo-authored reserved names are still dropped. An installed mod deriving the same name still wins it, and a distro server never counts for offers or kept.

### Changed

- **A start without a terminal opens the GUI** (T-2026-10-20-001, `#gui-relaunch`). `gnomon up` and bare `gnomon` with no interactive terminal, and `gnomon daemon start | --detach` / `gnomond` (activator) after a fresh start, open a new GUI window in the default browser. The single-use launch URL goes only to osascript's stdin and is never printed. **Opt out:** `--no-open` or `GNOMON_NO_OPEN=1`. `gnomond --foreground --no-open` is a usage refusal.
- **A stale GUI tab no longer points to a terminal as the only way back.** It says Gnomon stopped, treats an answer at its old address as unverified (it never suggests a reload), and offers "Close this tab" only when a same-origin window signals it attached.

### Security

- **Every user-writable directory on the session PATH is write-denied** (TD-2026-10-21-162, Aegis M, `#session-runner`, `#supervisor`, `#manifest-loader`). With `~/.local/bin` and the node directory ahead of `/usr/bin`, a session could plant an `ls` or `git` that a later session's auto-passed read-only command would run with no card. The `session` profile now denies writes (never reads or exec) to `~/.local/bin` (also a persistence path), the node directory (by realpath) when it is user-writable, a Homebrew prefix as a whole (`/opt/homebrew`; on `/usr/local` only `bin`, `sbin` and `Cellar`; found by realpath, never `HOMEBREW_PREFIX`), and any other user-writable PATH entry. A PATH entry that is the home or above it is dropped. Sessions can no longer `brew install` or `npm i -g` into those prefixes: Edit/Write is refused by Claude Code's permission rule and the shell gets `Operation not permitted`. The daemon's law-7 user-settings scan and claude source lookup use the OS home (`os.userInfo().homedir`), not `$HOME`.

- No web port is remembered across a restart (Aegis H1). Each plain start binds an OS-chosen port, and any `web-port.json` left over from the withdrawn build is deleted without being read.
